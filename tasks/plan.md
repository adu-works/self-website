## 节奏、估算与检查点

按一个开发者连续投入估算：M0 2–3、M1 4–6、M2 4–6、M3 6–9、M4 3–5、M5 3–4 个工作日，总计 22–33 个工作日；再预留约 20% 用于适配/视觉返工。不是交付承诺，不把 AI 产码时间等同于审核、内容准备和真实故障测试时间；M0 后按证据重估。

每 2–3 个任务提交一次可运行预览：检查测试、build、手动主路径，记录差异/问题/下一任务；里程碑向用户展示成果。检查点不是每次微小修改索要许可；G3→G4 与具体生产发布是明确关口。

每个任务完成条件：与需求编号对应、相关纯逻辑先测试、适当类型/输入校验、成功和失败路径、无密钥泄漏、学习日志写实际改动，才打勾。测试命令由 T04 的 package scripts 落实；以下未执行项不能预填通过。

## 风险与应对

| 风险 | 处理 | 触发调整 |
|---|---|---|
| 自带 Key 跨域/协议差异 | M0 优先验证服务端代理与 SSE；三厂商分适配 | 无法满足安全或费用约束则先重新评审通路 |
| 中文小语料召回不足 | 先测固定评估集；必要时加 pgvector 混合召回 | Recall@5 低于目标，不凭感觉扩栈 |
| 发布/索引不同步 | release 快照与原子指针，Outbox 重试 | 故障注入不能保持旧版可用则不进入上线 |
| 3D 性能与动作自然度 | 场景延迟加载、实机检查、降级阅读 | 目标手机过慢则降低纹理/细节或默认轻量入口 |
| 真实内容未备齐 | 保留待补状态，M1 用获准最小材料先交付 | 无真实内容则不声称首版内容上线 |
| 原型与实现审美失配 | 每类页面记录原型对照图，按内容块迁移 | 不以首页通过代替详情验收 |

## 方案评审需要确定

1. 是否采用 Next.js/TypeScript + Supabase，及可用地区/预算。
2. 是否接受访客 Key 经过本站请求代理但不持久化。
3. 首版三厂商与自定义 HTTPS 白名单策略。
4. 管理员登录账号、真实内容与社媒地址由本人提供；均不在公开仓库留秘密。
5. 同意里程碑顺序与验收目标后，明确批准 G4；未批准前任务均保持未开始。
