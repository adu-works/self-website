## 这次做了什么

用户再次否定上轮视觉，要求学习 Anime.js 引擎的拆解效果。本轮实际查看参考站的整机、拆开、线稿状态和公开首页脚本，确认其表达依靠分件机械模型、镜头、材料和后处理，而不只是给界面卡片加深度。重做原创环形机械体，代表个人空间的内容、阅读、公开检索与引用关系；它是概念模型，不是硬件或真实业务成果。

## 实现顺序（先写什么、再写什么，为什么）

1. 先核对参考站画面和组成：分件几何、轴向展开、材料转换、标签和光效。
2. 制作环体、齿圈、外壳、光圈叶片、转子和支柱；实例化重复部件，避免每个齿都单独渲染。
3. 建立六段纯镜头插值，再加入可暂停运转、按需加载和离屏清理。
4. 观察截图，修正线稿填充、边缘闪烁、旋转顺序和窄窗构图，完成自检后发布。

## 语言课堂（本次用到的 TS/Python 知识点）

本轮是 JavaScript/WebGL 原型，没有新增 TypeScript/Python 业务代码。

`Set` 用来登记 GPU 资源：同一个几何体被多个实例复用时，集合只保留一份，销毁时不会重复处理。`InstancedMesh` 则复用同一几何和材质，通过矩阵定义每个小齿的位置。

`root.rotation.order = 'ZYX'` 明确旋转组合的顺序。三维旋转不能交换顺序：沿自身轴旋转和把整机转成斜向构图会得到不同画面。不要只猜角度，要观察完整镜头。

插值 `a + (b - a) * t` 有浮点误差。测试发现末端的 -0.36 算成 -0.3599999999999999；现在 t 恰好为 0 或 1 时直接返回端点，保证整机合拢后精确回到初始变换。

## 测试

`node --test prototype/*.test.mjs`：17 项通过，三项镜头测试覆盖进度边界、六阶段、实体/线稿、外壳合拢、端点一致和可逆连续。

浏览器检查 1280×720 的整机、拆解与线稿；738×802 的拆解、检索、引用、暂停与恢复。390×844 显示六段完整说明、无横向溢出、场景 Canvas 为零；返回列表 Canvas 为零，观察到的 error 日志为空。

代码将绘制限制在可见区、目标上限约 30fps，但没有做真机帧率或耗电基准，不能把目标帧率当作测试结果。减少动效系统开关和 WebGL 丢失仍未专项实测。

## 扩展思考

“用了 Three.js”不等于达到了参考视觉。判断应分开检查几何细节、材质、灯光、构图、镜头节奏和界面可读性。对高完成度参考，先完成一个具有足够细节的主体，再做页面文字与导航，不要用技术名词代替视觉验收。
