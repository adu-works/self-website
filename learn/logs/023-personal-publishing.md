> 日期：2026-09-20 ｜ 对应路线图：G2 受影响范围重审 / G3 同步 ｜ 涉及代码：prototype/dist/personal.js、personal.css、index.html

## 这次做了什么

用户重新明确目标：个人影响力与售卖。原型默认直接呈现个人主页，文章覆盖技术、生活和商业；商品介绍与微信咨询形成独立路径。火星降为可选作品。真实业务没有实现。

## 实现顺序（先写什么、再写什么，为什么）

1. **先写首页和导航**，因为它们决定读者如何认识作者、找到内容与商品。
2. **然后写详情和演示流程**，因为只有首页漂亮无法验证阅读、咨询、订单与引用。
3. **最后检查返回、手机布局并同步文档**，因为入口变化会影响此前已认可的范围。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 默认入口 | 直接个人主页 | 降低读者认识作者和浏览商品的成本 | 强制探索：延迟主要任务 |
| 旧场景 | 暂留作品实验 | 不浪费可展示的交互成果 | 继续当首页：与最新用途不符 |
| 商品 | 示例价、目录、试读、微信说明 | 先验证理解与咨询路径 | 假支付成功：造成能力误解 |
| AI | 模拟公共资料回答 | 演示引用，无需真实凭据 | 原型收 Key：无必要 |

## 语言课堂（本次用到的 TS/Python 知识点）

本轮产品代码是 JavaScript/CSS，没有新增 TypeScript 或 Python 业务功能。实际使用的 JavaScript 示例：

```js
const list = articles.filter(a => a.category === state.category);
```

`filter` 从文章数组中选出符合条件的文章，返回新数组；不会删除原数组的文章。`===` 是比较，不能写成赋值的 `=`。本轮代码还会在“全部”分类时跳过分类条件。
