3. **最后按功能重写、合并并检查链接**，让需求、实现与验收在同一模块中对应。历史查 Git，不复制进新文档。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 解锁 | 建议服务端验证通用码，待用户选择 | 简单但有明确权限边界 | 前端遮罩不能满足本站 AI 与附件访问控制 |
| AI 受限内容 | 建议首版不发送给模型 | 解锁阅读不等于同意给第三方处理 | 默认全量索引容易泄露 |
| Agent | 建议直接依赖 AI SDK | 流式聊天和有限工具符合当前任务 | 整体搬入 Codex CLI 增加不需要的运行与权限范围 |
| 发布 | 单篇版本和数据库事务 | 小站易核查、失败可恢复 | 整站发布快照与独立 worker 当前过重 |
| 文档 | 8 份当前产品/工程文件 | 让用户能按问题找到答案 | 多份状态、任务、接口与历史叠加造成阅读负担 |

## 语言课堂（本次用到的 TS/Python 知识点）

没有编写新的 TS 产品代码。整理时实际使用 Python 的 `pathlib` 与正则检查本地 Markdown 链接：`p.parent / dest` 表示把文档所在目录与相对链接拼成目标路径，`.exists()` 检查目标是否存在。它只能检查文件存在，不能证明网页功能正确，也不验证网络链接状态。

本次实际整理脚本只存临时目录，不作为网站运行依赖。删除旧文档前先读取并迁移有效要求，既有 Git 历史保留旧稿。
