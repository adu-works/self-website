## 实现顺序（先写什么、再写什么，为什么）

1. 先区分固定入口与时间排序入口：自述固定，右卡按公开内容更新，这样不会把两种意图混在一起。
2. 再拆出首页内容模块，调整作品和书架；保留文章专题在文字栏目。
3. 最后给既有画廊加入视频模式，生成原始动态样片，检查播放、滚动和离开页面的清理，再同步文档。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 自述与关于 | 长文与简明介绍分开 | 支持两种了解深度 | 随机推荐：不能长期承担自述入口 |
| 最新动态 | 只比较成功对外发布的更新时间 | 后台草稿不干扰首页、不泄露未公开标题 | 比较任意 updatedAt：订单或草稿也可能顶上来 |

| 动效范围 | 页末有限滚动、手机横滑 | 不阻挡看文章与商品 | 整站强制 3D 导航：与当前目标不符 |

## 语言课堂（本次用到的 TS/Python 知识点）

本次实际写的是 JavaScript 原型，尚无 TypeScript 后端。

```js
records.filter(x => x.status === 'published' && Number.isFinite(Date.parse(x.contentUpdatedAt)))
```

`filter` 生成新数组，`=>` 是箭头函数，`&&` 表示两个条件都成立。`Date.parse` 将带时区日期转为可比较的毫秒值；无效日期会成为 `NaN`，用 `Number.isFinite` 排除。随后对新数组排序，不修改传入列表。生产应由服务器校验日期和发布权限，前端过滤不能成为权限边界。

```js
const observer = new IntersectionObserver(entries => {
  // 条目说明视频在视口中的可见比例；达到阈值才加入可播放集合。
}, { threshold: .35 });
```

视频预览不是一进入首页就全下载：进入视口后赋值 `src`，再调用 `play()`。它返回 Promise，浏览器可能拒绝自动播放，必须处理失败；封面和点击展开仍可用。打开全屏时暂停背景，路由退出时 `pause()`、`disconnect()` 并取消监听，防止声音或资源在后台残留。
