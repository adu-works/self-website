# 日志 035：窄窗口不应该关闭演示

> 日期：2026-09-21 ｜ 对应路线图：G2 原型修复 ｜ 涉及代码：prototype/dist/assembly.mjs、assembly.css

## 这次做了什么

用户反馈看不到三维。在线上复现 738×802 预览，DOM 显示 case-quiet 且 Canvas 为零：代码把所有 ≤760px 窗口都当手机了。修复为窄桌面上文下图，并显示静态模式的原因。

## 实现顺序（先写什么、再写什么，为什么）

1. 先在用户实际线上窗口点开作品，记录尺寸和降级状态，避免让用户重复刷新。
2. 调整触发条件，同时重排模型、说明和按钮，避免只改断点导致遮挡。
3. 按实际尺寸复验，再检查短窗口与手机，发布后在原线上窗口确认。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 窄桌面 | 上文下图，继续三维 | 桌面侧栏也常小于 760px | 一律静态：主要演示消失 |
| 降级 | ≤480px 或高度 ≤420px，以及减少动效/故障 | 极小空间优先可读 | 隐藏且不解释：用户不知道发生什么 |

## 语言课堂（本次用到的 TS/Python 知识点）

本轮实际使用 JavaScript 与 CSS，没有新增 TS/Python 业务逻辑。

`matchMedia('(max-width: 480px), (max-height: 420px), (prefers-reduced-motion: reduce)')` 中逗号表示“或”：任一条件满足即 matches 为 true。CSS 与 JavaScript 必须采用一致断点，否则可能出现代码加载模型但样式把舞台折叠的情况。

## 测试

本地浏览器 738×802 与 738×550 均显示一个三维 Canvas、无横向溢出；拆解画面和按钮可见。390×844 展示全部说明和静态提示。沿用纯逻辑测试，窗口问题依靠浏览器实际复现，不能由插值测试代替。

## 你自己动手（练习）

把浏览器缩至 738px，再缩至 390px，比较上文下图与静态模式。检查静态提示、页面宽度和重新放大后的三维是否恢复。

## 扩展思考

自动测试通过不等于用户可看到效果。验收应包含用户实际的面板尺寸，而不能只测 1280px 和 390px 两端。
