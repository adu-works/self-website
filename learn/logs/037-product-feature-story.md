# 日志 037：让项目本身成为展示主角

> 日期：2026-09-21 ｜ 对应路线图：G2 原型修订 / G3 同步 ｜ 涉及代码：prototype/dist/{case-content.mjs,assembly.mjs,project-scene.mjs,assembly.css,personal.js}

## 这次做了什么

把机械模型换成个人网站的十二段功能展示，用当前原型的实际页面讲阅读、书籍、作品、商品咨询和管理。没有实现真实后台或模型。

## 实现顺序（先写什么、再写什么，为什么）

1. 先列每段的用户价值、页面、要突出的组件，避免先造模型再套内容。
2. 再用实际页面做空间编排，正文/目录分层、书封展开、提案差异前移。
3. 最后逐段检查窄窗口、手机、返回与清理，修正自动聚焦导致镜头偏移的问题。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 展示对象 | 真实原型页面和局部组件 | 让观众看见具体功能 | 机械概念模型离用户实际目的过远 |
| 原型复用 | 同源只读展示框 | 避免手绘页面与实际内容分叉 | 为展示重写全部页面重复工作 |
| 正式实现 | 共享 React 组件与公开模拟数据 | 不嵌入真实后台和登录态 | 把原型 iframe 裁切方案直接当生产架构不稳定 |
| 生命周期 | 只保留相邻章节，离开销毁 | 不同时运行十二套页面 | 一开始加载全部章节浪费资源 |

## 语言课堂（本次用到的 TS/Python 知识点）

本次主要是浏览器 JavaScript，没有新增正式 TypeScript 后端。`Map` 按章节编号保存已挂载的元素；切换时删除不在当前范围的元素。`AbortController` 的 `signal` 可统一撤销注册的事件监听器，但还要单独断开观察器并取消动画帧。

`window.parent !== window` 判断页面是否在展示框内；配合明确的查询参数进入预览模式。它只是原型表现开关，**不是权限验证**。公开生产页面必须使用单独的模拟数据。

CSS 的 `perspective` 定义透视距离，`rotateY` 改变页面朝向，`translateZ` 改变层与镜头的距离。先保证文字能读，再增加空间变化。视效不能代替内容。

## 扩展思考

新作品不能照搬这十二段。先列它真实值得讲的功能，再设计合适的镜头；实际只有三个亮点就做三段，不为了长页面凑数。
