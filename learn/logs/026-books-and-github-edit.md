# 日志 026：书籍阅读与 GitHub 编辑入口

> 日期：2026-09-21 ｜ 对应路线图：G2 原型 / G3 设计补充 ｜ 涉及代码：prototype/books、build-books.mjs、dist/books.mjs、books.css

## 这次做了什么

新增书籍栏目、分章阅读、两级目录和标题边的源文件/编辑按钮。原创示例书稿进入本项目公开仓库，按钮逐章指向 Markdown；没有复制参考书内容。

## 实现顺序（先写什么、再写什么，为什么）

1. **先写示例源文件**，保证按钮对应真实文件。
2. **然后生成页面数据和阅读布局**，避免源文件与网页各写一份正文。
3. **最后验证链接、首尾与响应式**，确认目录在手机上不会把正文挤走。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 书稿事实来源 | 公开 Markdown | 读者能提出可审查修改 | 网页和书稿双写：容易不一致 |
| 编辑按钮 | GitHub 本章编辑链接 | 权限与 PR 由 GitHub 处理 | 点击直接改线上：缺少审查 |
| 付费书稿 | 不进入公开仓库 | 源码公开即允许读取正文 | 隐藏按钮：无法保护已上传内容 |

## 语言课堂（本次用到的 TS/Python 知识点）

产品使用 JavaScript 模块，没有新增 TS/Python 业务功能。生成脚本用 `await readFile(new URL(path, import.meta.url), 'utf8')`：`import.meta.url` 表示脚本所在位置，按它定位章节，避免启动命令的目录不同导致找错文件。`await` 等待文件读完再继续生成。

## 测试

语法、3 项导航测试、每章源文件与按钮路径及边界检查通过。浏览器验证章间切换，1440/390 宽度无横向溢出；手机两种目录默认折叠。未提交真实 PR，未测试 GitHub 登录。

## 你自己动手（练习）

1. 修改 chapter1.md 的一个段落，运行 `node prototype/build-books.mjs`，预览正文变化。
2. 对照章节页的“查看源文件”，确认指向的文件就是刚才修改的那一份。
