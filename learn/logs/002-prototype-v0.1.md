# 日志 002：原型 v0.1（可点击 HTML）

> 日期：2026-09-16 ｜ 对应路线图：G2 原型 ｜ 涉及代码：`docs/02-prototype/v0.1/`

## 这次做了什么

把 PRD 7.1 的页面清单变成一套能点、能切状态的静态 HTML 原型：14 个页面，覆盖 R01–R10，
外加 19 项空状态 / 加载 / 失败 / 越权 / 冲突等异常演示。它在产品里的角色是**评审工具**——
让用户在没有代码、没有服务器的情况下，先判断信息结构、措辞边界和确认流程对不对。
所有个人内容都是标注过的示例，页面顶部常驻紫色提示条，避免被误当事实。

## 实现顺序（先写什么、再写什么，为什么）

1. **先问四个问题再动手**（关口怎么处理、范围多大、内容从哪来、交付什么形式），因为这四件事任何一个猜错，整套原型都要重做。
2. **然后写 `assets/prototype.css` 和 `assets/prototype.js`**，因为 14 个页面共用导航、页脚、徽章、卡片、状态切换器。先把公共层定下来，后面每个页面才能只写自己的内容。
3. **再写展示类页面**（首页、经历、项目、见解），它们没有交互逻辑，最快验证公共层是否够用。
4. **再写交互类页面**（问答、项目内问答、管理端、预约），它们依赖公共层的 `Proto.fakeRequest` 等工具，而且逻辑最容易出错，放在结构稳定之后写。
5. **最后写索引类页面**（状态清单、移动端预览、README），它们要引用前面所有页面的锚点，必须等页面定稿。

核心心法不变：每一步结束都能在浏览器里打开看，不做"写完 14 个页面再一起调"的豪赌。

## 语言课堂（本次用到的 HTML/CSS/JS 知识点）

### 知识点 1：CSS 自定义属性（变量）

```css
:root {
  --accent: #1f6f5c;
  --line: #e2e0da;
}
.btn-primary { background: var(--accent); border-color: var(--accent); }
```

`:root` 是整个文档的根元素（就是 `<html>`）。以 `--` 开头的名字是自定义属性，用 `var(--名字)` 取值。
好处是评审时想换主色，只改 `:root` 里一行，全站跟着变。常见错误：写成 `background: --accent`（漏了 `var()`），或在 `var()` 里写错名字——写错时属性会**静默失效**，不报错，所以改完要刷新页面确认。

### 知识点 2：data-* 属性 + 属性选择器，做"状态切换器"

```html
<select data-state-switch="list">…</select>
<div data-state-group="list" data-state="empty">…</div>
```

```js
var panels = document.querySelectorAll('[data-state-group="' + group + '"]');
panels.forEach(function (panel) {
  panel.hidden = panel.getAttribute('data-state') !== select.value;
});
```

HTML 允许任何以 `data-` 开头的自定义属性，用来给元素挂业务含义。`querySelectorAll('[属性="值"]')` 是属性选择器，按属性找元素。
`panel.hidden = true` 对应 HTML 的 `hidden` 属性，浏览器会隐藏元素，而且屏幕阅读器也不会读到——比 `style.display='none'` 语义更清楚。
常见错误：忘了在页面加载时先调用一次同步函数，结果初始状态和下拉框显示的不一致。

### 知识点 3：IIFE（立即执行函数）隔离作用域

```js
(function () {
  'use strict';
  var log = document.getElementById('log');
  // …
})();
```

`(function(){…})()` 的意思是"定义一个函数并马上调用它"。里面用 `var` 声明的变量只活在这个函数内部，不会污染全局。
这里每个页面都有自己的 `log`、`input`，如果直接写在全局，多个脚本同名变量就会互相覆盖。`'use strict'` 打开严格模式，把"手滑写错变量名却自动创建全局变量"这类问题变成报错。

### 知识点 4：事件委托

```js
box.addEventListener('click', function (e) {
  var btn = e.target.closest('[data-act]');
  if (!btn) return;
  // 根据 btn 上的 data-act / data-id 决定做什么
});
```

管理端的按钮在每次 `render()` 后都是全新的 DOM 节点，逐个绑定事件既啰嗦又容易漏。
改成在**容器**上监听一次点击，事件冒泡上来后用 `e.target.closest(选择器)` 找到真正被点的按钮。
`closest` 会从被点元素开始往上找最近的匹配祖先，所以点到按钮内部的文字也能正确命中。常见错误：忘记 `if (!btn) return;`，点空白处时后面的代码拿到 `null` 就报错。

### 知识点 5：`@supports` 特性检测与降级

```css
.site-header { background: rgba(234, 237, 235, .72); backdrop-filter: blur(16px); }

@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .site-header { background: var(--paper); }
}
```

`@supports` 问浏览器"你支持这条声明吗"，支持才应用里面的规则；`not (...)` 就是反过来。
这里的用处是：头部做成半透明毛玻璃很好看，但如果浏览器不支持 `backdrop-filter`，半透明背景下的正文会透上来和头部文字叠在一起。
所以给不支持的环境准备实色背景。常见错误：只测自己的浏览器，忘了降级路径——我这次就是在截图里看到文字叠在一起才发现的。

### 知识点 6：响应式断点

```css
@media (max-width: 860px) {
  .grid-3 { grid-template-columns: 1fr; }
  .nav { display: none; }
  .nav[data-open="true"] { display: flex; }
}
```

`@media` 里的规则只在条件成立时生效。这里的做法是"桌面优先"：先写宽屏样式，再在窄屏覆盖。
导航的展开用属性 `data-open` 控制，JS 只负责改属性值，样式全在 CSS 里——逻辑和外观分开，改样式不用动 JS。

## 测试

这一轮没有自动化测试（还没有构建系统，也还没批准技术栈）。做的是浏览器实测：
用 `python3 -m http.server` 起本地服务，逐页检查公共导航是否注入成功、状态切换是否真的切换、
管理端四条路径（确认成功 / 重复确认 / 确认失效 / 失败恢复）是否都能走到、预约冲突是否明确说"没有创建"、390px 宽度下导航是否折叠，并收集控制台报错。

实测确实抓到一个问题：管理端"重复确认"的黄色提示原本渲染在按钮**下方**，点完按钮后视线还停在原处，不滚动就看不到，验证时一度被判成"这个功能没做"。
DOM 里有内容不等于用户看得到——提示要出现在触发它的控件**上方**。已改并复验。

局限要说清楚：这是人工核对，不是回归测试。进入实现阶段后，纯逻辑部分（例如提案状态机）应该先有单元测试再实现。
另外，这次的浏览器验证是交给子 Agent 做的，它报告的截图路径实际并不存在——**别人给的验证结论要自己抽查关键项**，尤其是被标成"可能未实现"的那一条。

## 补记：视觉重做（同日，v0.1.1）

用户问"是不是该用一些设计 skill"，一句话点中了问题：第一版 CSS 是按默认审美写的——暖米色底、衬线标题、绿色点缀，正好是 AI 生成设计最常见的三种长相之一。读了设计方向、Apple 界面与动效原则、Web Interface Guidelines 三份材料后重做。

做法上的关键变化是**先定方向再写代码**。方向叫「核对台」：这个站的主张是"每句话都能回到来源"，那视觉系统就应该把"核对"这个动作做出来，而不是套一个好看的模板。落地成一个签名元素——正文主张后面挂等宽小编号，划过时对应来源被荧光笔标亮，首页标题本身就在演示它。其余部分保持安静：颜色只有六个语义值，标记色只用在证据高亮和当前位置两处。

从 Apple 那套原则里只取了静态页面用得上的部分：按下即反馈（`:active` 缩放发生在按下瞬间）、半透明头部让内容从下面穿过、字号越大字距越紧行距越小、三种无障碍偏好（减少动效 / 减少透明 / 提高对比）各有对应处理。手势、弹簧、速度接力这些跟静态原型无关，没有硬套。

界面规范清单查出并修掉的问题：缺少"跳到主内容"链接、异步区域没有 `aria-live`、表单缺 `autocomplete`/`type`/`name`、占位符不以省略号结尾、两个假链接（`href="#"` + `onclick`）应该是按钮、中文里混用直引号。

浏览器实测又抓到三个真缺陷：移动端菜单半透明导致正文透上来两层字叠在一起（改成实色，并给不支持 `backdrop-filter` 的环境加实色兜底）；问答页"提问"按钮被输入框挤成两行（按钮加 `white-space: nowrap` 和 `flex: 0 0 auto`）；以及前面提过的重复确认提示位置。

## 再补记：第二次视觉重做（v0.1.2）

用户看完第一次重做的结论是"太丑，能不能高级一些，弄些动效，去调研别人的个人网站"。这次没有再凭手感改，而是先建立参照系。

调研了 rauno.me、paco.me 这类设计工程师的个人站和 Codrops 2026 的作品集专题，得到一个挺反直觉的结论：**创意开发者**的站点靠 WebGL 和电影感取胜，而**工程师**的站点恰恰相反——排版优先、大留白、几乎没有边框和色块，高级感来自精度而不是元素密度。Rauno 在《Designing Depth》里那句话直接决定了动效怎么做：自然界里树叶不会同时晃动，界面里同组元素也该错峰出现，错峰本身就是深度。

还做了一件事解决"看不清设计"的问题：加了「评审标注」开关。需求编号、示例说明、状态切换器这些评审脚手架一键收起，用户才能只看产品本身。这条已经写进 SOP。

### 语言课堂（这次新用到的）

#### IntersectionObserver：元素进入视口时才播放动画

```js
var io = new IntersectionObserver(function (entries) {
  entries.forEach(function (entry) {
    if (!entry.isIntersecting) return;
    entry.target.classList.add('is-in');
    io.unobserve(entry.target);   // 播放过就不再观察，省性能
  });
}, { rootMargin: '0px 0px -8% 0px', threshold: .05 });
```

以前要做"滚动到这里再动"，得监听 `scroll` 事件并不断计算位置，既啰嗦又容易卡。`IntersectionObserver` 由浏览器在后台判断"目标和视口有没有相交"，相交时才回调。
`threshold: .05` 表示露出 5% 就算进入；`rootMargin` 把判定线往上收 8%，让动画早一点点开始。常见错误：忘了 `unobserve`，元素反复进出视口会重复触发。

#### 用 CSS 变量传递错峰延迟

```js
child.style.setProperty('--reveal-delay', (i * 55) + 'ms');
```

```css
.reveal.is-in { transition-delay: var(--reveal-delay, 0ms); }
```

JS 只负责算出"你是第几个"，具体怎么动全写在 CSS 里。这样调动效节奏时只改 CSS，不用碰逻辑。
`var(--reveal-delay, 0ms)` 里的第二个参数是**兜底值**——变量没设置时用 0ms，不会整条声明失效。

#### `data-theme` 属性 + 变量覆盖实现深色模式

```css
:root { --bg: #fbfbfc; --ink: #17181c; }
[data-theme="dark"] { --bg: #0b0b0d; --ink: #ecedef; }
```

所有组件只写 `background: var(--bg)`，不写具体颜色。换主题时只需要在 `<html>` 上改一个属性，整站颜色跟着变。
配套细节：`color-scheme` 让滚动条和表单控件也跟着换；主题选择存进 `localStorage`，下次进来保持一致；脚本在 `DOMContentLoaded` **之前**就先应用主题，避免深色偏好下先闪一下白底。

## 第三次重做：从"页面"变成"工作台"（v0.2）

前两版都没对，根因是参照系选错了。我自己找的参照是 rauno.me、paco.me 这类"设计工程师的克制路线"，而用户心里的参照是**体验型**——他直接给了 11 个链接，里面 `alanagoyal.com/finder` 是 macOS Finder 克隆，`sharyap.com` 是 "shar's desktop"，`bruno-simon.com` 是 3D 开车游戏，`animejs.com` 是动画库自己的游乐场。共同点是：**站点本身就是一个可玩的作品**。

方向定为「个人工作台 OS」。选它不是因为好玩，而是它和产品内核对得上：项目和见解本来就是文件，站长 Agent 的"提案→确认"本来就是系统对话框，全站问答本来就是聚光灯搜索。

### 一个关键的工程决定

窗口内容用 **iframe 装载既有页面**，而不是把 14 个页面的内容重新搬进新外壳。

这样做的理由是风险控制：那些页面里的问答五态、提案确认与失败回滚，都是逐项验证过的；搬运一次就等于把它们重新置于风险之中。用 iframe，则外壳和内容彻底解耦——这次换外壳，内容一行没改。

配套加了"嵌入模式"：页面用 `window.self !== window.top` 判断自己是否在窗口里，若是就移除自己的顶栏和页脚（窗口标题栏已经承担了这个职责），主题也跟随外壳。单独打开时行为完全不变。

### 语言课堂（这次新用到的）

#### 指针捕获：拖动时不怕鼠标跑出元素

```js
bar.addEventListener('pointerdown', function (e) {
  try { bar.setPointerCapture(e.pointerId); } catch (err) { /* 合成事件时忽略 */ }
  // 之后的 pointermove 即使指针移到元素外，也仍然发给 bar
});
```

不用捕获的话，鼠标一快、指针离开标题栏，`pointermove` 就发给别的元素了，窗口会"掉手"。
`setPointerCapture` 把这个指针的后续事件**锁定**在当前元素上，直到 `pointerup`。
那个 `try/catch` 是我测试时踩出来的：用脚本合成的 `PointerEvent` 没有真实指针，调用会抛错。真实交互不受影响，但加上更稳。

#### transform-origin 让窗口"从图标里长出来"

```js
var ox = ((iconRect.left + iconRect.width / 2) - winLeft) / winWidth * 100;
win.style.setProperty('--origin-x', ox + '%');
```

```css
.window { transform-origin: var(--origin-x) var(--origin-y); animation: win-open 280ms; }
@keyframes win-open { from { opacity: 0; transform: scale(.88); } }
```

同样是"缩放淡入"，缩放中心在窗口正中，看起来就是个普通弹窗；缩放中心落在**你刚点的那个图标**上，就变成"窗口从图标里展开"。
这是 Apple 界面设计里那条"锚定来源"原则：东西从哪儿来，就该从哪儿长出来。计算就是把图标中心点换算成窗口内部的百分比坐标。

#### 手机端的下拉关闭：松手才决定去留

```js
function onMove(e) {
  moved = Math.max(0, e.clientY - startY);
  win.style.transform = 'translateY(' + moved + 'px)';   // 1:1 跟手
}
function onUp() {
  if (moved > 110) closeWindow(id);                       // 过阈值才关
  else { win.style.transition = 'transform 320ms'; win.style.transform = ''; }  // 否则弹回
}
```

关键是**过程中 1:1 跟手、松手时才判定**。如果改成"一检测到下滑就关闭"，用户会觉得失控；先跟手再判定，手感就对了。`Math.max(0, …)` 保证只能往下拖，往上拖没有反应。

## 返工记录：批量替换引号把页面改坏了

把中文直引号统一换成弯引号时，我写的正则只看"引号两侧是不是中文"，没有区分这个引号在哪儿。结果 `aria-label="管理端分区"` 的结束引号因为前一个字符是中文也被替换，标签结构被破坏，管理端左侧导航直接渲染错乱；内联脚本里 HTML 字符串的属性引号同样中招。

发现方式是改完后重新抓页面结构，看到 `管理端分区”>           <button type=` 这种明显不对的可访问性名称。

修复不是简单撤销（文件里本来就有合法的弯引号，无法反推），而是按区域重新处理：标签内和 `<script>` 内一律还原成直引号，只在正文文本里按出现顺序交替配对。然后加了一条自动校验——每个标签内的直引号数量必须是偶数——确认 14 个文件全部干净，再逐页跑脚本语法检查。

**可迁移的教训：批量替换前必须先界定作用域。**同一个字符在属性、字符串字面量和正文里含义完全不同；改完要跑结构校验，不能只看替换了多少处。

## 扩展思考

现在 14 个页面各自复制了 `<head>` 和页面骨架，改一次公共结构要动 14 个文件。真做实现时这就是模板引擎或框架要解决的问题。
但要注意：**原型里用静态 HTML 是刻意的**，它保证评审者零依赖打开；实现阶段选什么框架是另一个问题，不要因为原型是 HTML 就默认用某个方案。
另一个会变的点：管理端的提案状态机现在写在页面脚本里，真实现时它属于后端领域逻辑，前端只是展示——迁移时要重新划分职责，而不是把这段 JS 搬过去。
