# 日志 015：内容内页的编辑设计

> 日期：2026-09-17 ｜ 对应路线图：G2 原型 ｜ 涉及代码：docs/02-prototype/v1.1/dist/detail-views.js、editorial.css、app.js

## 这次做了什么

项目与文章从共用窄栏模板改为内容专属排版；关于延续首页信纸隐喻，联系页使用独立大标题。保持现有引用与返回行为。

## 实现顺序（先写什么、再写什么，为什么）

1. 读数据与路由，确认稳定章节 ID 和上下文问答入口。
2. 拆出展示模板，再用局部 CSS 建立封面、章节、旁注与继续阅读。
3. 检查桌面、手机和页面关系，修正纸卡字号后发布。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 内页风格 | 作品案例、编辑手记、信纸 | 延续入口物件并适配内容 | 通用正文模板缺少内容个性 |
| 引用兼容 | 保持章节 ID | 旧引用仍能找到依据 | 改布局同时改 ID 会断链 |
| 素材 | 已有场景图与 CSS 纸卡 | 内容与视觉对应，不虚构成果 | 无关图库难以解释项目 |

## 语言课堂（本次用到的 TS/Python 知识点）

本次业务改动是 JavaScript 和 CSS，没有新增 TS/Python 业务实现。

```js
export function detailView(type,item,{back,update=''}) { /* 返回页面模板 */ }
```

`export` 让其他文件能导入该函数；第三个参数使用对象解构，省略 `update` 时默认为空字符串。视图只返回 HTML，导航仍交给原控制器。

CSS Grid 用列定义区分目录与正文；媒体查询在窄屏改成单列，避免用固定宽度挤压文字。

## 测试

12 项原有回归通过，两个 JS 语法检查通过。浏览器检查桌面封面、章节、关于、联系与手记；390px 文章和索引页无横向溢出。检查章节按钮、引用高亮和焦点、下一篇、关于与联系往返。

## 你自己动手（练习）

把一个项目摘要改长一倍，观察桌面与手机换行；保持章节 ID 不变，验证引用仍能跳转。

## 扩展思考

正式内容管理应将章节、引文、图注等作为内容结构，设计层负责排版；避免每篇文章都手写布局。
