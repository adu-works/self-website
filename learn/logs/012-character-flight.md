# 日志 012：角色握持与归航演绎

> 日期：2026-09-16 ｜ 对应路线图：G2 原型修订 ｜ 涉及代码：docs/02-prototype/v1.1/dist/{character-rig.js,scene.js,flight.js,flight-sequence.mjs,app.js}

## 这次做了什么

修正铲子与手臂脱离、搬炉后不能走的原型问题，补齐火箭飞行、入大气层、落地开舱伸展及视线进入 Chat。保持模拟配置和原型边界。

## 实现顺序（先写什么、再写什么，为什么）

1. **先检查已有模型和状态机**，找到手腕骨骼、动画名、缩放及阻止移动的语句，避免只换文案。
2. **然后拆出骨骼插槽与时间线**，再将道具和动作接入，确保工具有固定依附点、各段事件有固定顺序。
3. **最后浏览器走流程并补检查**，观察负重、铲子和飞行，修正炉体遮挡、出舱仍带铲子及舱口被实心外壳遮住的问题。测试和观感不能相互替代。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 工具依附 | 手掌骨骼插槽 | 走路/铲土时保持相对手的位置 | 每帧在人物旁摆位置会漂浮 |
| 搬运 | 保留步行下肢，叠加双臂姿态 | 不再引入跪姿 | 持枪动画不适合搬炉 |
| 归航 | 单条时间线 | 镜头和事件共用进度 | 多个页面计时器容易提前藏掉飞船 |
| 最终目的地 | 完整 Chat | 用户明确回答 | 自动进主站已被本轮澄清替代 |

## 语言课堂（本次用到的 TS/Python 知识点）

本次产品代码为 JavaScript，没有新增 TypeScript 或 Python 产品模块。实际用到：

```js
socket.add(shovel);
rig?.pose('carry');
```

第一句把铲子作为手部插槽的子物体，之后坐标相对手部；第二句的 `?.` 是可选链，模型没加载完时不调用，避免空对象错误。父子关系还会继承缩放，因此读取骨骼比例后需要在插槽中抵消模型的 100 倍骨架比例。

## 测试

执行 `node --test terrain.test.mjs shortcuts.test.mjs rig-flight.test.mjs`。后者加载实际 GLB，采样步行动画并叠加搬运姿态，检查髋部未被搬运姿态下压、工具插槽不脱离；同时检查各镜头时间段连续。浏览器实际走通搬炉移动放下、锻造取铲越坡挖宝、配置登船、归航与 Chat；具体记录在原型 VALIDATION.md。

## 你自己动手（练习）
