## 实现顺序（先写什么、再写什么，为什么）

1. 先对照实际页面，分清可借鉴的时间节奏、空间关系和不适合照搬的红黑视觉/模型。
2. 将组装的进度分段，先完成一块，再进入下一块；加可点击的阶段入口，减少被迫滚动。
3. 修正视频生命周期与书架边界，最后检查电脑、390px 与短窗口，同步模块设计。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 作品动效 | 文字、作品、小店、完整空间四段 | 画面变化对应读者价值 | 多块同时漂浮：只剩装饰 |
| 视频收回 | 同片缩回，换片淡出回原入口 | 不把 B 内容缩回 A 封面 | 始终缩回：内容身份不连续 |
| 书架 | 随位置轻转，不自动播放 | 让滑动有反馈，阅读可控 | 复制视频画廊的大幅滚动：多个区块抢注意力 |
| 小屏与短窗 | 静态可读布局 | 避免 sticky 内容裁切 | 强保桌面动画：入口可能到不了 |

## 语言课堂（本次用到的 TS/Python 知识点）

本次使用 JavaScript 原型，没有新增 TypeScript/Python 业务代码。

```js
const arrival = Math.max(0, Math.min(1, (progress - index * .28) / .23));
```

`index` 是第几块面板，乘以 `.28` 决定开始时刻，除以 `.23` 决定运动持续的进度区间。`Math.min` 和 `Math.max` 把结果限制在 0 到 1，保证反向滚动仍能恢复对应姿态。开始间隔大于持续区间，因此前一块先归位，下一块再动。

视频使用 `Map` 以片段编号记录 `currentTime`。等待 `loadedmetadata` 后再设播放位置，避免时长未知；事件使用 `{ once: true, signal }`，只执行一次，也能随路由清理。`disposed` 表示所属页面已离开，防止异步转场结束后再次操作被移除的窗口。
