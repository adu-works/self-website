## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 地形 | 网格与脚下共用 heightAt | 视觉地面与移动不能各用一份高度 | 独立半球装饰：角色会从中穿过 |
| 动作 | 三锤、五铲、独立开门 | 每次输入都有明确反馈 | 自动播放整段：用户明确不接受 |
| 角色资源 | CC0 骨骼模型 | 有真正步行动画且来源可核对 | 原始简化人体：动作表达太弱 |
| 主站 | 归航桌面与专注阅读页 | 物件给内容入口个性，阅读保持稳定 | 大标题+标准卡片首屏：本轮明确返工 |
| 引用 | 路由加段落 ID | 能核对一段具体依据 | 仅打开文章首页：不能完成精准核对 |

## 语言课堂（本次实际使用 JavaScript；未新增 TS/Python 产品功能）

### 知识点 1：一个函数被两个地方复用

```js
export function heightAt(x,z){ /* 计算这里的地面高度 */ }
```

`export` 表示别的文件可以使用这个函数。地形生成和角色移动都调用它，避免两处计算不同造成角色穿地。`x,z` 是地面上的两个方向，返回值是垂直高度。改山坡应改这个函数，而不是另放一个看起来像山的球体。

### 知识点 2：只有完成动作后才增加计数

```js
animate('dig',()=>{
  state.digs++;
  if(state.digs===5) state.stage='uncovered';
},1150);
```

`()=>{...}` 是稍后执行的函数。`++` 表示加一，`===` 检查是否等于目标次数。按钮点击开始动画，动画结束才执行加一；忙碌期间按钮禁用，因此快速连点不能跳过五铲。

### 知识点 3：引用保存的是地址，不是网页代码

```js
{label:'一个回答，也应该有来路',route:'article/sources/section-1'}
```

这个对象把人能读懂的名字与页面定位信息放在一起。页面先根据文章 ID 找内容，再根据 section-1 找段落；正文进入 HTML 前仍转义，不能把提问文字当代码执行。

## 扩展思考

正式实现需要决定角色脚部 IK、移动设备画质分档、可维护内容 ID 和真正的引用检索。原型用连续高度解决主要穿坡问题，但仍不等于完整游戏物理；真实模型问答必须有独立权限与密钥方案。
