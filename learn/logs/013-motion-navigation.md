## 这次做了什么

把挖土和伸展改为分段动作，出舱镜头绕至肩后再接视线；统一站内返回逻辑，并修正配置、工作台与恢复弹窗的页面关系。

## 实现顺序（先写什么、再写什么，为什么）

1. **先枚举入口与返回**，找到详情固定回栏目、锚点强行回 Chat、清除配置不同步地址等具体问题。
2. **然后拆出历史与动作曲线模块**，用纯逻辑测试验证返回链、后备页、镜头接缝和动作归零，再接入现有原型。
3. **最后浏览器按来源往返与观察动作**，保留筛选和草稿，核实工作台状态；发现关节偏移累积后加入基准复位与重复采样测试。

## 关键决策

| 决策点 | 选择 | 为什么 | 落选方案 & 为什么 |
|---|---|---|---|
| 返回 | 回退已有站内历史项 | 不制造 A→B→A→B 的假返回链 | 固定跳列表忽略真实来源 |
| 直接链接 | 安全后备页 | 没有来源就不猜测 | 盲目 history.back 可能离开站点 |
| 工作台结果 | 状态独立保存、按页面显示 | 离开再返回仍可核对结果 | 依赖工作台挂载会让任务悬空 |
| 动作偏移 | 每帧相对基准计算 | 未被动画重写的骨骼也不累加变形 | 持续减角度会越弯越多 |
| 出舱视角 | 侧向绕至肩后 | 视线推进有连续方向 | 正面直推会穿过脸部 |

## 语言课堂（本次用到的 TS/Python 知识点）

本次使用 JavaScript，没有新增 TS/Python 产品代码。实际片段：

```js
const entries = new Map();
entries.set(current.id, current);
host.history.back();
```

`Map` 按历史项 ID 保存本次访问的视图。`history.back()` 退回已有记录，与重新打开前页不同：重新打开会再新增一条记录。快照保留筛选和滚动；它不是跨刷新数据库，也不会保存真实凭据。
