# 功能实现方案

> v3.2 待评审 · 2026-09-21。本文是开发设计，不是已实现能力；G4 未开始。

## 先回答：用什么语言

现在的原型是 HTML、CSS、JavaScript，没有业务后端。旧方案推荐 TypeScript 全栈；结合你希望掌握 Python，本版建议 **前端 TypeScript，后端 Python**。数据库操作还会涉及 SQL，文章与书稿使用 Markdown。

前端用 Next.js / React，后端用 FastAPI。Python 负责认证检查、文章发布、订单权益和 Agent；Next.js 负责界面与页面渲染。代价是维护两个运行环境和接口契约，收益是后端职责清楚，能围绕真实功能系统学习 Python。这个调整仍需你确认，不代表你已批准开工。

产品规则看 [PRD](PRD.md)，具体模块设计看 [modules/](modules/)，开发次序只维护在 [PLAN](PLAN.md)。本文只说明把这些功能连起来的方法。

## 一次请求怎么走

读者打开页面 → Next.js 请求 Python 的公开接口 → Python 只查询已发布内容 → 返回公开字段 → 页面呈现。

站长提交修改 → Python 验证登录和站长身份 → Pydantic 校验请求 → 业务服务检查版本与规则 → SQLAlchemy 在事务内写入 PostgreSQL → 返回新版本 → 页面更新。Agent 确认也走同一个业务服务，模型没有数据库凭据。

建议目录（尚未创建）：

```text
web/                     Next.js 页面、组件、API 客户端和测试
backend/
  app/main.py            创建应用、挂载路由
  app/core/              配置、认证、日志、数据库会话
  app/content/           文章与版本
  app/books/             公开书籍与导入
  app/commerce/          商品、客户、订单与人工交付
  app/ai/                公开检索、模型适配、站长提案
  migrations/            Alembic 数据库变更
  tests/                 逻辑测试和 PostgreSQL 集成测试
docs/reviews/            每个已实现功能的临时评审稿，按需创建
learn/features/          用户通过后生成的正式实现与教学文档
```

每个后端模块按需要包含路由、输入输出模型、业务服务和数据模型，不为一个简单查询增加多层抽象。先选择同步数据库事务方式；模型流式调用使用异步客户端，不能把同步阻塞数据库调用直接放进事件循环。实际接入时通过并发测试核实，避免为学习而堆叠所有异步语法。

## 登录和数据权限

首版只有站长登录，买家不必注册。建议 Supabase Auth 提供身份认证；登录会话由 Python 服务端管理，浏览器只持有随机会话 ID 的 Secure、HttpOnly、SameSite Cookie，刷新凭据不放 localStorage。会话表保存会话 ID 摘要；必须持久化的刷新凭据加密保存，密钥独立于数据库。登录、刷新、退出和到期作为第一个独立功能验收。

Python 使用可信验证库或认证服务校验身份，检查签名、发行者、受众与到期，不能仅解码 JWT。再以配置中的站长用户 ID 判断管理权限，不能把“已登录”当“站长”。写请求同时校验 CSRF 与来源；退出撤销本站会话，过期拒绝写入。[Supabase JWT 官方说明](https://supabase.com/docs/guides/auth/jwts)

业务数据库使用独立受限角色；迁移用独立高权限角色。业务表不向匿名和普通 authenticated 角色开放，开启 RLS 并核查直连/Data API 均不能绕过权限。后端权限检查仍然必须执行。公开接口使用专门输出模型，禁止直接返回完整 ORM 对象，防止客户信息和内部飞书字段泄漏。私有附件只在站长鉴权后短时签名访问。

## 每个功能怎么落地

| 功能 | 前后端配合与数据 | 最重要的验收 |
|---|---|---|
| 首页、文章、专题、社媒 | 前端按原型组件化；后端按已发布版本提供列表、详情、专题顺序和段落锚点 | 直接链接可打开；返回保留来源/滚动位置；草稿不出现在搜索 |
| 内容编辑 | Markdown 编辑、导入和预览；`contents/revisions/sections/series/assets` 保存版本与段落 | 不执行 HTML/MDX；上传限制类型和大小；冲突不覆盖 |
| 发布、撤回、恢复 | 新版本、段落和发布指针在同一事务更新；恢复旧版先生成草稿 | 发布失败无半成品；撤回后公开读取与检索均不可获得正文 |
| 书籍 | 每书配置可信仓库、固定提交和公开文件清单；导入清理后的章节，保留 Git 来源 | 拒绝路径越界；不执行仓库脚本；私有稿不入公开产物；源码按钮对应实际发布版本 |
| 商品 | 公共介绍与内部资源映射分开输出；商品页复制联系信息，不创建付款记录 | 隐藏字段确实不在响应里；下架不破坏旧订单 |
| 客户与订单 | 站长登记核实后的身份、交易参考、实收和商品快照；修订保留事件 | 重名不混淆；重复登记被识别；修改商品不改变历史订单 |
| 交付与权益 | 分别记录已开通、已发送、期限、撤权核验；待办由数据和当前时间计算 | 到期不冒充飞书已撤权；续购或其他有效订单阻止误撤权 |
| 公开 AI | 先做公开内容检索 API；根据决策接网页限额模型或公开 Skill | 无访客模型 Key；无草稿、付费正文和内部资源；引用有真实段落 |
| 站长 Agent | Python SDK 调用只读工具并形成提案；前端展示差异；确认接口保存草稿 | 重复确认一次生效；旧提案报冲突；发布另行确认；模型故障不阻塞人工编辑 |

书稿以 Git 为正文来源，网站数据库只是发布副本，不让普通编辑器形成第二份可写正文。构建/导入失败保留上个发布版本；仓库配置变更需预览。查看源文件链接固定发布提交，编辑链接指向维护分支并提示可能已有更新。完整私有书稿不进入网站构建环境，只导入明确批准的公开导出文件。细节见 [书籍模块](modules/07-books.md)。

飞书首版纯人工授权，没有权限同步 API。商品期限保存类型与数值，实际授权以站长核实时间为依据；数据库时间用带时区时间戳，页面显示 Asia/Shanghai。金额使用整数分与币种，不用浮点数；长期权益明确表示，无需用夸张的未来日期。退款、收款和飞书操作均只登记已人工核实的事实。

## 接口约定与异常

所有接口放在 `/api/`；公开内容与 `/api/admin/` 管理入口分开。FastAPI 的输入/输出模型生成 OpenAPI，前端由契约生成类型，CI 检查契约变化；Python 类型标注本身不能替代请求校验。[FastAPI 官方说明](https://fastapi.tiangolo.com/features/)

代表接口：公开 `GET /api/contents/{slug}`、`GET /api/books/{book}/chapters/{chapter}`；管理 `PUT /api/admin/contents/{id}/draft`、`POST /api/admin/contents/{id}/publish`、`POST /api/admin/orders`、`POST /api/admin/proposals/{id}/confirm`。其他接口在对应功能实现前确定，不提前生成大量空路由。

写接口绑定基础版本；冲突返回 409，未登录 401，无管理权限 403，输入不合法 422，限流 429。错误有稳定错误码、可读说明和请求编号，不泄漏堆栈、SQL、Cookie 或正文。订单登记、发布与提案确认带幂等标识：同一标识和内容重试返回既有结果，换内容重用标识拒绝。幂等记录与业务写入同事务提交。

断网时前端查询操作状态，不能直接宣称失败并重复写。确认凭据绑定对象、版本、动作与有效期；任何内容变化都使旧确认失效。每个请求独立数据库会话，失败回滚，不在等待模型响应时占用写事务。

公开 AI 先用小规模中文关键词检索基线，测试同义词和无答案问题；不足再评估向量检索。服务器给检索片段分配来源 ID，模型只能引用这些 ID；输出时再次核查公开状态与来源，前端生成链接。撤回阻止新的读取，无法收回读者此前已收到的文字。网页 Chat 若获批，必须有共享的限额/并发与每日费用上限控制，不只依赖单进程内存计数。

## 开发、测试与上线

Python 依赖用 `pyproject.toml` 和锁文件管理；前端同样锁定依赖。环境变量有假值模板和启动校验。通过部署试点后再确定具体语言版本与托管商；不把未经运行的命令写成已经验证。

每个功能先写核心规则测试，再接数据库与页面。后端用 pytest + 实际 PostgreSQL 测试事务、约束和迁移，不用 SQLite 替代这些验证；Ruff 和 mypy 检查格式及类型。前端用 Vitest 检查必要状态逻辑，Playwright 验证用户关键操作、权限和错误出口。测试环境只放假客户和假交易。

生产同域代理分流网页与 Python API，配置 HTTPS、流式超时、请求大小和速率限制；认证与私有响应禁止共享缓存。初版公开正文也不设共享缓存，优先保证撤回一致性。预览/生产数据库、存储和凭据隔离。迁移先备份再验证，优先兼容旧应用；应用回滚不能假定数据库降级安全，涉及破坏性迁移另评审。

上线验收覆盖手机/键盘、身份越权、并发写、备份恢复、日志脱敏和断网。日志只记录必要请求编号、耗时、状态，不默认记录模型原始提示、客户资料和秘密。展示具体预览及检查结果后才请求正式发布确认。

## 每个功能怎样交给你

先交 `docs/reviews/Fxx.md`：开头直接告诉你“改了什么、先看哪些文件、怎样验收、有哪些风险”，随后写实现细节与验证证据。你明确通过前只修订本功能，不能以测试通过代替你的 review。

通过后生成 `learn/features/Fxx.md`，按“环境 → 最小可运行版本 → 数据与规则 → 接口 → 页面 → 测试 → 排错”的顺序教你复建；每一步有对应代码、命令、预期结果及选择原因，解释本功能真实用到的 Python 语法，并给独立练习和参考解法。教材检查完成后才删除临时稿，Git 保留历史。详细执行要求写在 [AGENTS.md](../AGENTS.md)。

现在只交方案，不伪造实现评审稿与教学成果。该流程增加交付时间，因此规划按小功能推进，评审等待与返工不藏在一个过度乐观的总工期里。
