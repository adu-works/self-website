# 功能实现方案

> v3.5 待评审 · 2026-09-21。本文是开发设计，不是已实现能力；G4 未开始。

## 先回答：用什么语言

现在的原型是 HTML、CSS、JavaScript，没有业务后端。本项目采用 **TypeScript 全栈**：Next.js / React 做界面，Next.js Route Handlers 在 Node.js 服务端处理 API；PostgreSQL 保存数据。数据库还会涉及 SQL，书稿使用 Markdown。

这是针对当前个人网站的综合选择，不是说 TypeScript 对所有项目都最优。内容发布、商品订单与有限工具 Agent 都能在同一应用内实现；共享输入模型、一次部署、统一测试工具能减少个人维护成本。Python 更适合已有 Python 服务或需要其专属计算库的情况，本项目目前没有这些依赖。调用模型 API 本身不要求 Python。

用户本轮明确表示“TypeScript 全栈最优的话就使用 TypeScript 全栈”，据此确定语言方向；其他 G3 设计仍待评审，不代表正式开发已获批准。教学重心相应改为 TypeScript、Node.js、SQL 与 Web 工程，逐后端功能评审流程保留。

产品规则看 [PRD](PRD.md)，具体模块设计看 [modules/](modules/)，开发次序只维护在 [PLAN](PLAN.md)。本文只说明把这些功能连起来的方法。

## 一次请求怎么走

读者打开页面 → 服务端读取已发布内容 → 返回公开字段 → 页面呈现。服务器组件直接调用只读业务服务，浏览器和 Skill 通过公开 API 访问，不让服务端绕一圈 HTTP 调自己。

站长提交修改 → 服务端验证登录和站长身份 → Zod 校验请求 → 业务服务检查版本与规则 → Drizzle 在事务内写入 PostgreSQL → 返回新版本 → 页面更新。Agent 确认也走同一个业务服务，模型没有数据库凭据。

建议目录（尚未创建）：

```text
src/app/                 页面和 app/api/**/route.ts 接口入口
src/components/          页面组件
src/contracts/           可安全共享的 Zod 输入/输出模型和类型
src/server/core/         配置、认证、日志、数据库连接
src/server/content/      文章与版本
src/server/books/        公开书籍与导入
src/server/commerce/     商品、客户、订单与人工交付
src/server/ai/           公开检索、模型适配、站长提案
drizzle/                 经检查的 SQL 迁移文件
tests/                   逻辑、PostgreSQL 集成和页面测试
docs/reviews/            每个已实现功能的临时评审稿，按需创建
learn/features/          用户通过后生成的正式实现与教学文档
```

路由只处理 HTTP、鉴权和输入输出，业务服务负责规则与事务，数据层负责查询。服务端模块标记 `server-only`，客户端不能导入数据库或秘密；共享目录只放公开安全的契约。数据库与网络调用使用异步 API，不在等待模型响应时占用数据库事务，不为简单功能增加微服务。

## 登录和数据权限

首版只有站长登录，买家不必注册。建议 Supabase Auth 提供身份认证；登录会话由 Node.js 服务端管理，浏览器只持有随机会话 ID 的 Secure、HttpOnly、SameSite Cookie，刷新凭据不放 localStorage。会话表保存会话 ID 摘要；必须持久化的刷新凭据加密保存，密钥独立于数据库。登录、刷新、退出和到期作为第一个独立功能验收。

服务端使用可信验证库或认证服务校验身份，检查签名、发行者、受众与到期，不能仅解码 JWT。再以配置中的站长用户 ID 判断管理权限，不能把“已登录”当“站长”。写请求同时校验 CSRF 与来源；退出撤销本站会话，过期拒绝写入。[Supabase JWT 官方说明](https://supabase.com/docs/guides/auth/jwts)

业务数据库使用独立受限角色；迁移用独立高权限角色。业务表不向匿名和普通 authenticated 角色开放，开启 RLS 并核查直连/Data API 均不能绕过权限。后端权限检查仍然必须执行。公开接口使用专门输出模型，禁止直接返回完整 ORM 对象，防止客户信息和内部飞书字段泄漏。私有附件只在站长鉴权后短时签名访问。

## 每个功能怎么落地

| 功能 | 前后端配合与数据 | 最重要的验收 |
|---|---|---|
| 首页、文章、专题、社媒 | 前端按原型组件化；后端按已发布版本提供列表、详情、专题顺序和段落锚点 | 直接链接可打开；返回保留来源/滚动位置；草稿不出现在搜索 |
| 内容编辑 | Markdown 编辑、导入和预览；`contents/revisions/sections/series/assets` 保存版本与段落 | 不执行 HTML/MDX；上传限制类型和大小；冲突不覆盖 |
| 发布、撤回、恢复 | 新版本、段落和发布指针在同一事务更新；恢复旧版先生成草稿 | 发布失败无半成品；撤回后公开读取与检索均不可获得正文 |
| 书籍 | 每书配置可信仓库、固定提交和公开文件清单；导入清理后的章节，保留 Git 来源 | 拒绝路径越界；不执行仓库脚本；私有稿不入公开产物；源码按钮对应实际发布版本 |
| 商品 | 公共介绍与内部资源映射分开输出；商品页复制联系信息，不创建付款记录 | 隐藏字段确实不在响应里；下架不破坏旧订单 |
| 客户与订单 | 站长登记核实后的身份、交易参考、实收和商品快照；修订保留事件 | 重名不混淆；重复登记被识别；修改商品不改变历史订单 |
| 交付与权益 | 分别记录已开通、已发送、期限、撤权核验；待办由数据和当前时间计算 | 到期不冒充飞书已撤权；续购或其他有效订单阻止误撤权 |
| 公开 AI | 先做公开内容检索 API；根据决策接网页限额模型或公开 Skill | 无访客模型 Key；无草稿、付费正文和内部资源；引用有真实段落 |
| 站长 Agent | AI SDK 调用只读工具并形成提案；前端展示差异；确认接口保存草稿 | 重复确认一次生效；旧提案报冲突；发布另行确认；模型故障不阻塞人工编辑 |

书稿以 Git 为正文来源，网站数据库只是发布副本，不让普通编辑器形成第二份可写正文。构建/导入失败保留上个发布版本；仓库配置变更需预览。查看源文件链接固定发布提交，编辑链接指向维护分支并提示可能已有更新。完整私有书稿不进入网站构建环境，只导入明确批准的公开导出文件。细节见 [书籍模块](modules/07-books.md)。

飞书首版纯人工授权，没有权限同步 API。商品期限保存类型与数值，实际授权以站长核实时间为依据；数据库时间用带时区时间戳，页面显示 Asia/Shanghai。金额使用整数分与币种，不用浮点数；长期权益明确表示，无需用夸张的未来日期。退款、收款和飞书操作均只登记已人工核实的事实。

## 首页内容与动效

首页由内容服务提供主题句、固定自述、最近文章、精选作品、书籍、商品和视频。最新动态统一比较公开版本的 `publicContentUpdatedAt`，输出类型、标题、摘要和站内链接；不查询草稿正文。撤回、下架后立即排除，无内容返回空状态。F04 先支持已完成模块的内容类型；F05/F06 接入后扩展书籍和商品，不倒置依赖。

书架用原生横向滚动与吸附，保留按钮和键盘操作。生活视频在页面末尾，用可见性观察器延迟载入预览；离屏或后台标签暂停，最多同时预览两段。建议每段预览 5—8 秒、每段不超过 1 MB，正式资源以试点测量后调整；原型三段合计不足 300 KB。完整视频只在点击时加载。减少动效使用静态封面，移动端不用纵向滚动锁定。退出页面清理监听器、动画与视频，避免后台继续耗资源。

## 接口约定与异常

所有接口放在 `/api/`；公开内容与 `/api/admin/` 管理入口分开。Route Handlers 使用 Node.js 运行时。前后端共享 Zod 契约并推导 TypeScript 类型；后端仍必须运行时校验，不能认为类型共享就等于安全。面向外部 Skill 的接口另提供稳定说明与契约测试。[Next.js 接口说明](https://nextjs.org/docs/app/getting-started/route-handlers)

数据层建议 Drizzle ORM 配合 PostgreSQL 驱动，迁移 SQL 纳入评审，生产不直接推送未经检查的表结构。发布、幂等和提案确认使用数据库事务。[Drizzle 事务说明](https://orm.drizzle.team/docs/transactions)

代表接口：公开 `GET /api/contents/{slug}`、`GET /api/books/{book}/chapters/{chapter}`；管理 `PUT /api/admin/contents/{id}/draft`、`POST /api/admin/contents/{id}/publish`、`POST /api/admin/orders`、`POST /api/admin/proposals/{id}/confirm`。其他接口在对应功能实现前确定，不提前生成大量空路由。

写接口绑定基础版本；冲突返回 409，未登录 401，无管理权限 403，输入不合法 422，限流 429。错误有稳定错误码、可读说明和请求编号，不泄漏堆栈、SQL、Cookie 或正文。订单登记、发布与提案确认带幂等标识：同一标识和内容重试返回既有结果，换内容重用标识拒绝。幂等记录与业务写入同事务提交。

断网时前端查询操作状态，不能直接宣称失败并重复写。确认凭据绑定对象、版本、动作与有效期；任何内容变化都使旧确认失效。连接池复用连接，每次业务事务独立，失败回滚，不在等待模型响应时占用写事务。

公开 AI 先用小规模中文关键词检索基线，测试同义词和无答案问题；不足再评估向量检索。服务器给检索片段分配来源 ID，模型只能引用这些 ID；输出时再次核查公开状态与来源，前端生成链接。撤回阻止新的读取，无法收回读者此前已收到的文字。网页 Chat 若获批，必须有共享的限额/并发与每日费用上限控制，不只依赖单进程内存计数。

## 开发、测试与上线

应用依赖用 `package.json` 与 pnpm 锁文件管理，固定 Node.js 和包管理器版本。环境变量有假值模板和启动校验。通过部署试点后再确定具体语言版本与托管商；不把未经运行的命令写成已经验证。

每个功能先写核心规则测试，再接数据库与页面。后端用 Vitest + 实际 PostgreSQL 测试事务、约束和迁移，不用 SQLite 替代这些验证；ESLint、格式检查和 `tsc --noEmit` 检查代码及类型。前端用 Vitest 检查必要状态逻辑，Playwright 验证用户关键操作、权限和错误出口。测试环境只放假客户和假交易。

生产部署一个 Next.js Node.js 应用，同时提供网页与 API，配置 HTTPS、流式超时、请求大小和速率限制；认证与私有响应禁止共享缓存。初版公开正文也不设共享缓存，优先保证撤回一致性。预览/生产数据库、存储和凭据隔离。迁移先备份再验证，优先兼容旧应用；应用回滚不能假定数据库降级安全，涉及破坏性迁移另评审。

上线验收覆盖手机/键盘、身份越权、并发写、备份恢复、日志脱敏和断网。日志只记录必要请求编号、耗时、状态，不默认记录模型原始提示、客户资料和秘密。展示具体预览及检查结果后才请求正式发布确认。

## 每个功能怎样交给你

先交 `docs/reviews/Fxx.md`：开头直接告诉你“改了什么、先看哪些文件、怎样验收、有哪些风险”，随后写实现细节与验证证据。你明确通过前只修订本功能，不能以测试通过代替你的 review。

通过后生成 `learn/features/Fxx.md`，按“环境 → 最小可运行版本 → 数据与规则 → 接口 → 页面 → 测试 → 排错”的顺序教你复建；每一步有对应代码、命令、预期结果及选择原因，解释本功能真实用到的 TypeScript / Node.js 语法与工程实践，并给独立练习和参考解法。教材检查完成后才删除临时稿，Git 保留历史。详细执行要求写在 [AGENTS.md](../AGENTS.md)。

现在只交方案，不伪造实现评审稿与教学成果。该流程增加交付时间，因此规划按小功能推进，评审等待与返工不藏在一个过度乐观的总工期里。

## 作品演示的实现边界

作品列表只有作品。F04 的项目详情可按需加载 Three.js，依据具体作品展示整机、拆解、线稿透视、功能聚焦与合拢；首页与列表不加载该包。正文、元信息和项目说明仍为可索引 HTML，Canvas 不承担唯一的信息入口。原型先验证镜头；正式实现再确定资源预算并测真机。手机、短窗口、减少动效与 WebGL 故障均用静态内容；可见区运转动画限频并可暂停，离屏及隐藏停止绘制；组件卸载释放 GPU、渲染目标和监听器。此方案待 G3 评审，不代表正式功能已实现。
