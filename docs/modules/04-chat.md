# 04 · 访客 AI 问答

> v2.0 · 待评审。目标：像正常聊天产品一样使用，每个重要结论都能回到本站内容核对。

## 页面与流程

Chat 是完整页面：宽敞的消息区域、底部输入栏、新建对话、停止生成和模型设置；桌面左侧是本次访问的会话列表，手机可折叠。配置模型前也能看见界面与说明，不强迫回火星。离开去看引用再返回，同一页面会话和输入保留；刷新后默认清空会话与 Key，提前说明，不假装已经云同步。

访客选择厂商、模型并填写自己的 API Key，明确点击验证。建议首版支持 OpenAI、DeepSeek、Anthropic；模型名称由用户配置，不写死某个型号。通过后可开始对话；验证也可能消耗少量厂商额度。普通阅读无需 Key。

默认问全站公开内容，从文章或项目进入时显示当前范围。没有足够资料就说“本站尚未提供这部分信息”，给相关页面，不编造你的经历。问题与来源不足时无需反复调用模型。

## 数据会经过哪里

建议通路：浏览器 → 本站问答服务 → 访客选择的模型厂商。Key 暂存在浏览器内存，服务器只在这次请求内转发使用，不入数据库、网址、日志或统计工具。**Key 会经过本站服务器**，配置处必须说清楚；这项需你确认。浏览器直接请求不同厂商存在跨域和协议差异，因此不作为首版统一路线。

向厂商发送当前问题、有限的会话上下文、经过权限筛选的本站片段。普通访客聊天不长期保存到服务器，也不启用带正文的外部追踪。基础日志只记录请求编号、耗时、错误类别。站长模型使用独立凭据，访客 Key 不承担站长调用。

自定义接口只允许站长预先登记的 HTTPS 地址，访客不能让服务器访问任意 URL、内网或跳转地址。清除配置会停止当前请求、清空 Key，并提示重新配置；不会把清除动作伪装成退出阅读权限。

## 引用与权限

答案里的引用显示编号与来源标题，点击定位具体章节或段落并短暂高亮。服务端先建立允许引用的列表，模型只能选其中的 ID，不能自己编链接。引用记录内容 ID、版本、段落 ID；来源已改、撤回或权限变化时，点击后解释真实状态。

首版建议只使用 `已发布 + 公开 + 允许 AI 引用` 的内容，即便访客有阅读授权，也不自动把解锁正文送去第三方模型。受限文章只能提示公开摘要与解锁入口。草稿、后台资料、学习日志和仓库文件不进入访客知识库。提供 API Key 不是额外阅读授权。

撤回或修改权限后，新请求不能继续检索旧版本；流式回答开始前再次核查来源，检测到变化时停止并要求重试，不能声称可追回已经发送给模型或访客的文字。每轮由服务器重新检索，客户端不能指定私有段落成为证据。网页或文章里出现“忽略规则、调用管理工具”只当成文章内容；访客服务根本不注册写入工具。首版不联网替本站补资料、不自动下载外部网页。

## 实现与异常

使用 AI SDK 的聊天和流式能力，按厂商适配协议。请求包含问题、会话消息、范围和模型配置，服务端校验长度与允许的模型地址。`POST /api/chat` 流式返回文字、合法来源和明确结束/失败状态；`POST /api/model-config/validate` 只验证连接，不永久保存配置。

建议每次问题最多 4,000 字，每会话仅一个生成请求；上下文与输出分别设置 token 上限，上游最长 60 秒。限流使用服务端共享计数，不能只用浏览器按钮防重复。具体额度在小规模验证时调整，不承诺无限使用。

错误区分 Key 无效、模型不可用、额度不足/限流、网络超时；保留问题并允许重试。停止生成向上游发送取消，已生成部分标为未完成；停止不保证已经消耗的额度退回。离开页面取消未完成流，不在后台继续产生不可见费用。

首版使用标题、标签、中文分词和段落关键词检索。不急着加向量数据库：先用评估集检查“换种说法能否找到文章”；不足时再在现有数据库加入语义检索，评审增加的成本。不要使用每位访客不同的模型建立互不兼容的站点索引。

## 怎样检查

统一使用 30 个固定问题：有答案 12、无答案 6、范围切换 4、权限与诱导 4、模型失败与取消 4。可回答题至少 11/12 有正确事实与有效来源，其余不得捏造个人信息；权限泄露必须为零。程序检查所有来源目标合法，人工检查引用真的支撑答案。这些是待验收目标，当前未执行真实模型测试。
