# 04 · 用户自己的 AI、Skill 与内容 API

> v2.1 讨论稿 · 2026-09-20 · 推荐取消访客填写模型厂商 Key 的入口；用户尚未确认替换原有 Chat 方案，原型保持不动。

## 我的推荐

主站提供公开阅读、会员阅读和普通搜索；AI 用户通过 Skill 接入你的只读内容 API。首版不收集或转发访客的模型 Key，也不把安装 Skill 作为网页阅读的必经步骤。

网页公共 Chat 有两个可评审选项：暂缓真实聊天，归航落点改成“搜索 / 接入我的 AI”；或者保留完整 Chat，由站长支付一个限额模型，仅回答公开资料。推荐先做前者控制成本与范围，但这改变此前明确的“落地进入完整 Chat”，必须由用户确认。不能悄悄把原型 Chat 改成安装说明，也不能擅自增加站长模型支出。

## Skill 到底负责什么

Skill 是指令和可选脚本的包，告诉用户的 AI 何时搜索、怎样获取片段、怎样标注来源。用户可以查看或修改它，因此 Skill 内的检查只改善提示，不能决定付费授权。真正的验证在本站服务器，每次请求都要检查。

最小通路：用户提问 → 用户 AI 按 Skill 调用本地连接工具 → 本站内容 API 检查令牌、套餐、到期和额度 → 返回允许的片段与来源 → 用户 AI 生成答案。模型厂商 Key 留在用户原有 AI 环境，不传本站。

Skill 包不附付费全集、不嵌入个人令牌、不要求把令牌粘贴到聊天里。安装程序或连接工具从操作系统凭据存储（优先）或受保护的环境配置读取内容令牌，通过 HTTPS Authorization 请求头发送；不放 URL、模型工具参数、控制台输出或普通日志。工具只接受查询词、文章 ID 和段落 ID，固定连接本站域名。

这种设计能减少模型直接看到凭据的机会，但不能保证用户电脑上有文件或执行权限的 Agent、插件或恶意软件永远读不到它。安全依赖宿主环境；权限和额度必须限制在我们的服务器上。

## 内容 API 最小范围

| 接口/工具 | 作用 | 服务器规则 |
|---|---|---|
| `getAccess` | 返回套餐、期限与剩余用量 | 只查自己的授权，不返回令牌原值 |
| `searchContent` | 按问题找相关文章 | 先筛选权限，再搜索和返回少量片段 |
| `readSection` | 读取指定文章段落 | 再次检查文章、版本、套餐和 AI 开关 |

每条结果有标题、内容 ID、版本、段落 ID、来源 URL 和更新时间。首版不提供付费全集导出、批量遍历或任意 URL 抓取。设置每用户总用量、每令牌速率、并发和单次返回字数限制，所有令牌合计不能绕过账号总额；超额停止新请求，不产生未同意的超额账单。具体数值在试点测量后确定。

分段返回与限流降低批量提取速度，不构成防复制保证。正常订阅者仍能反复查询，也可保存结果。Skill 建议引用来源和不编造，但对用户任意修改的客户端不能保证输出质量；本站能保证的是返回片段的权限、版本与来源。

## 令牌如何管理

这里的 API Key 建议叫“内容访问令牌”，避免和模型 Key 混淆。由服务端生成高熵随机值，仅创建时显示一次；数据库保存摘要、前缀、账户、范围、有效期和撤销状态。用户可以按设备创建、查看最近使用、单独撤销与重建。

令牌只给只读内容权限，不给管理员、支付或模型额度权限。泄露后仍可能导致已授权内容被获取和配额被消耗；只是影响范围比用户的模型厂商 Key 更可控。每次请求都查当前权益，订阅到期或撤销立即阻断新访问；不依赖长期自包含 token 中的旧订阅状态。

日志隐藏 Authorization、cookie 与正文敏感字段；部署代理、错误追踪和应用都要检查，不能只在业务代码里“不写日志”。安全基础参考 [OWASP 秘密管理](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html) 与 [REST 安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。

## Skill、API 与 MCP 怎么选

先做一个确定的只读内容 API，再为一个明确支持的 AI 客户端提供 Skill 和连接工具，验证安装、凭据保存、调用与引用。不承诺所有聊天应用都能安装 Skill 或联网执行脚本。

如果目标客户端支持远程 MCP，可增加薄适配层，复用同一权限服务，通过 OAuth 登录授权、短期访问令牌和可撤销会话减少手抄长期密钥。它改善凭据流转，不阻止客户端读取已授权内容；还需验证客户端支持与授权服务，不能说一用 MCP 就安全。首版无需同时自建完整 API Key 和 OAuth 平台。

参考：[Agent Skills 格式](https://agentskills.io/home)、[MCP 授权规范](https://modelcontextprotocol.io/specification/latest/basic/authorization)，2026-09-20 核对。远程 HTTP MCP 的授权与本地脚本凭据不是同一种配置方式。

## 付费内容会经过哪里

返回给用户 AI 的付费片段可能进入其模型供应商、聊天历史、客户端缓存或其他工具。不要宣传“允许用户 AI 阅读但付费内容永不离开本站”。撤销订阅只能阻止新的服务器请求，不能删除第三方已收到的内容。

如果接受这个边界，订阅卖的是持续更新、可靠检索与便捷使用；如果不能接受，就不提供付费内容 API，Skill 只能查询公开内容。不能通过提示词要求“不可保存”来替代技术授权。

## 原 BYOK 方案安全吗

HTTPS、内存暂存、不持久化、日志脱敏、最小权限等可以降低风险，但不能实现零风险：前端脚本被植入、依赖受攻击、服务器或日志链路配置错误都可能泄露请求中的 Key。只说“不保存”不够，服务器处理请求时仍能接触它。

取消入口能从本站责任范围中移除访客模型凭据；新的内容令牌仍需要保护，用户客户端也仍有风险。两者不能简单等同，也不能承诺“换成 Skill 就不会泄露”。

## 怎样验收

用公开、付费可供 AI、付费禁止 AI、草稿和撤回五类样本测试。伪造会员、猜段落 ID、修改 Skill 跳过校验、多 Key 绕额度、旧 token 重放都不能越权；测试撤销、到期、续费、限流和超时。检查令牌不进入模型输入、日志和分享链接；实际走通至少一个明确标注支持的客户端。原 30 题网页模型评估不能直接代替内容 API 权限测试。
