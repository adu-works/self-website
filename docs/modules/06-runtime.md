## 火星体验怎么保留

两条路线：打造铲子 → 多次挖掘 → 宝箱配置模型 → 船票 → 火箭归航 → 完整 Chat；或搬起熔炉 → 砸下 → 主站，也始终提供直接浏览。搬起后能放下并保留进度。配置失败或取消不清空探索进度，后续直接从 Chat 配置无需重新玩。

键盘移动与动作按钮并存；每次按键只触发一次动作，不抢输入框或输入法。爬坡服从地形高度，炉子、火箭有碰撞；铲子跟随手部。挖掘与伸展有准备、发力和收势，负重慢走不能套用单膝跪地姿势。

归航统一控制火箭、环境、人物与镜头的时间线：起飞 → 太空 → 穿过大气层 → 落地 → 开舱出舱 → 伸展 → 肩后跟随 → 顺目光切到 Chat。切镜表达目光方向，不让摄像机穿头。可跳过、可重看；无论哪种结束方式都到完整 Chat。

以上继承已认可的 v1.1.6；本次只补文字与权限方案，不改原型画面。新增后台和公众号流程尚未在原型中实现，需在开发前补充针对这些流程的轻量评审，不重做整个火星场景。

## 技术怎么组成

| 部分 | 推荐选择 | 为什么 |
|---|---|---|
| 网页与服务端 | Next.js + TypeScript | 一套语言完成界面、内容接口和流式回答，方便你学习与修改 |
| 数据、登录、图片 | Supabase 的 PostgreSQL、Auth、Storage | 减少自己维护账号与上传服务；权限仍由我们设计和验证 |
| 模型接入 | Vercel AI SDK | 共用流式和工具基础，保持访客与站长权限独立 |
| 火星 | 独立 Three.js 模块 | 重用原型素材与纯逻辑，不让 3D 拖累阅读页 |
| 检查 | Zod、Vitest、Playwright | 分别检查输入、纯逻辑和真实页面操作 |

以上均是推荐，未购买或安装。开发起点先验证部署地区网络、流式连接与厂商接入，再锁定依赖版本。正式部署需要支持服务端的环境；Sites 当前承载静态原型，不能被当作现成的正式权限后台。[Next.js 自托管说明](https://nextjs.org/docs/app/guides/self-hosting)

数据库开启行级权限，匿名不能直接读草稿或受限正文；对外接口在服务器统一检查。服务端高权限密钥不发浏览器，使用它的代码不能绕过本站权限规则。[Supabase 权限说明](https://supabase.com/docs/guides/database/postgres/row-level-security)

建议正式代码按 `content`、`access`、`chat`、`admin-agent`、`scene` 五个功能目录组织；接口靠近所属模块。先不建微服务、独立向量库、消息队列或全站发布快照。单篇内容版本加数据库事务足够支撑当前规模；达到瓶颈再扩展。

## 加载与降级

先显示可读主站，进入探索才下载大型 3D 资源。离开场景释放渲染、监听器和显存。手机减少细节，WebGL 不可用显示“直接阅读 / 前往 Chat”；尊重减少动效设置，不强制声音。

首版正文请求不走共享内容缓存，以简化撤回和权限变更的一致性；图片与静态代码按公开/私有分开处理。公开页面仍提供标题、摘要与搜索引擎所需信息。若以后加缓存，必须先证明受限全文不会跨用户共享。

## 上线前必须真的做的事

- 用示例数据通过全流程，再按你提供的材料替换；不能把 mock 项目成果当真。
- 390px 手机和 1440px 桌面检查阅读、导航、Chat、解锁；检查键盘、200% 放大和减少动效。
- 核实部署区域实际可达、模型调用成功、权限隔离、流式停止与超时。费用包括网站、数据库、存储、流量及站长模型；访客 Key 只支付访客自己的模型费用。
- 数据库和私有附件定期备份，至少做一次恢复演练。上线前记录备份保留时间、恢复步骤与旧应用版本；不把“有备份开关”当作可恢复。
- 预览与正式环境隔离，用环境变量保存秘密；公开仓库只放源码和假配置模板。
- 部署前展示具体预览及检查结果，由你批准该次正式发布。回滚应用和恢复内容是两条独立路径，都要能操作。

预算、域名与地区在部署验证前补齐；现在不要求你为了看方案就提供真实文章、履历或所有账号。
