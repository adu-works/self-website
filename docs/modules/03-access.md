# 03 · 商品、客户与飞书交付

> v2.2 讨论稿 · 2026-09-20 · 按用户最新倾向设计：网站展示商品，微信私下付款，每晚人工处理，飞书授权交付。正式开发未开始。

## 这版怎么分工

网站是展示与咨询入口；微信是沟通和收款渠道；后台记录客户、订单和权益期限；飞书保存付费正文并实际控制谁能读。公众号只是另一个内容与推广窗口，不承担会员校验。

首版建议按商品出售固定期限或长期阅读权，不做自动续费。每份商品单独设置权益，买一份不等于开通全站会员。不要求买家先注册我们的网站；后台有客户档案即可，以后确有需求再增加自助会员中心。

## 商品卡片与详情

每张卡片显示封面、名称、简短介绍、明确售价、访问期限、更新状态和“加微信咨询购买”。详情增加适合谁、能获得什么、目录、明确标注的试读、更新/答疑范围、飞书账号要求、交付时间和退款说明。正式售价、期限、承诺由站长填写，开发用示例，不能把占位价格发布为真实报价。

商品页只展示明确公开的字段，不包含付费正文或内部飞书链接；服务端不能把内部字段一起发送给浏览器后仅靠隐藏控制。商品下架后不再接受新咨询，但保留旧订单当时的商品名称、价格和权益快照。

弹窗建议文案：

> 添加我的微信，备注「购买：{商品名称} / {商品编号}」。
> 请先确认内容与访问期限，再付款。
> 我会在每天晚上集中核对订单并开通飞书阅读权限，非即时发货；当晚处理后的消息顺延至下一处理时段。
> 请准备你实际用于阅读的飞书账号。

按钮：复制微信号、复制购买备注、保存联系二维码、关闭。二维码为联系二维码，不是付款二维码。弹窗可键盘关闭，手机内容可滚动；实际微信资料未提供时使用明确示例且不开放真实购买。具体晚间时段、时区和节假日安排由站长后补，页面不要虚构固定几点发货。

打开弹窗或复制备注只代表咨询意向，不能自动创建“已付款”订单。站长实际核对收款记录后才登记实收；不把买家的转账截图当作已核验到账。

## 每晚怎样处理

1. 打开“待处理”：先核对新增付款，确认商品与买家的飞书身份。
2. 登记订单，关联客户、实收、收款时间及必要交易参考；推荐访问期从实际开通时起算，避免等待交付占用购买天数。
3. 到飞书给对应账号开通该商品的只读权限，核对没有顺带授权其他商品；再发送链接。
4. 返回后台分别记录“已开通”“已发送链接”，录入实际起止时间。链接已发但没权限不能标为已交付。
5. 检查即将到期、已到期待撤权、退款待处理和交付失败；逐项处理后记录结果。忘记处理的事项第二天继续保留。

后台提供交付话术的复制功能，不在首版自动发微信或操作个人微信。这里描述的是产品待办流程，不是现在已创建定时提醒或自动任务。

## 后台只做真正用得上的部分

| 页面 | 主要信息与操作 |
|---|---|
| 商品管理 | 介绍、售价、期限、目录、试读、上下架、内部飞书资源映射 |
| 客户管理 | 内部客户编号、微信备注/联系标识、核实的飞书账号、所购商品；不要只靠重名昵称匹配 |
| 订单管理 | 商品权益快照、实收、交易参考、付款时间、备注、退款记录；错误修订留历史，不悄悄覆盖 |
| 权益与交付 | 谁能看哪份资源、开通/到期时间、链接发送记录、实际撤权状态、最近核对时间 |
| 今日待办 | 已付款待开通、已开通待发送、身份待核实、即将到期、到期待撤权、退款待处理 |

付款状态、交付状态、权限状态分别记录。比如“已退款 + 待撤权”是真实可能的状态，不能用一个“完成”遮盖。后台仅站长可读写；客户与交易记录不进入公开 Git、网页搜索、公共 AI 或外部追踪日志。

建议最小数据：`products`、`customers`、`orders`、`entitlements`、`delivery_events`，资源映射随商品管理。未自动接飞书时，权限状态要标“站长于某时核对”，不能伪装为实时读取。按钮只更新后台记录，不宣称已替用户改变飞书。

## 飞书怎么授权才成立

采用指定买家账号的只读授权，关闭面向任意持链接者的阅读。链接只是入口，买家身份才是访问条件。不要用一个共享密码代替所有买家的身份，否则无法单独撤销一个人。

每个商品对应可独立授权的文档集合或空间；不要把买家加入包含所有商品的大群、文件夹或知识库。一个商品有多份资源时维护完整资源清单，新添或移动文档也要检查继承权限。撤销时检查直接授权、上级继承、群组成员等其他入口，防止删掉一处仍能读。

正式采用前，用站长账号、买家 A、无权限买家 B 做试点：A 能读指定商品，B 拿链接仍不能读；A 看不到其他商品；撤权后 A 不能再次获取正文。还要核实外部协作者、组织分享策略、套餐/人数限制与手机体验。不让买家成为内部员工来绕过外部分享限制。

飞书官方确认有分享、安全权限配置，以及协作者权限管理能力；本次未登录你的飞书实测，不能保证当前账号具备全部配置或自动到期能力。[文档权限设置](https://www.feishu.cn/hc/zh-CN/articles/265017155035)、[云文档权限接口说明入口](https://www.feishu.cn/content/383321056779)。

## 到期、续购与退款

- 到期前进入提醒列表；到期后后台标“合同权益已到期，飞书待撤权”。站长去飞书处理并核验后才标已撤权。
- 纯人工晚间处理无法保证到期那一秒撤权。推荐权益统一到站长当天处理窗口结束，提前告知处理规则；若要求精确自动到期，需要先验证飞书能力或开发可靠的权限同步任务。
- 续购增加新订单，保留旧记录。默认从原到期与新开通时间的较晚者续算；去撤权前重新检查是否有续购或其他有效订单。
- 一个人经多笔订单获得同一资源时，只在没有任何有效权益后才移除权限，不能退款一单就误伤另一单。
- 退款是否受理、全额/部分退款与权益终止时点必须事先写明；实际退款核对后更新账目，并单独处理撤权。需要返还款项的操作不由 Agent 自动执行。

## “防复制”能承诺到哪里

我们可以限制未授权访问，按飞书实际可用能力限制复制、下载、打印、创建副本及再分享；可用时开启适合外部读者的身份水印。水印与部分安全能力需核实账号版本和外部访问效果，不能只测站长自己的屏幕。

这些能降低随手转发与批量复制风险，不能杜绝截图、拍照、OCR、人工转录或已经下载的内容。网站公开介绍也不可能完全防复制；不靠禁右键、禁选中文字冒充安全机制，不破坏正常阅读和无障碍。

此前付费 Skill/API 会将可处理的内容交给用户 AI，与严格防复制目标有冲突。建议首版暂缓付费 API，只允许公共 AI 使用公开资料；是否保留付费 Skill 是待用户确认的取舍。单纯将内容移到飞书不会自动让两者兼容。

## 何时才值得自动化

先记录实际订单量、平均交付耗时和漏处理情况，再决定是否接自动支付或权限同步。人工方案省开发但增加每天处理成本；不能宣传自动到账、自动发货或自动到期。

将来优先自动化到期核对和失败提醒；飞书授权 API 的资源类型、外部成员身份、应用权限与继承规则验证通过后，才允许明确授权的同步操作。当前不安装应用、不接收真实付款、不发送微信或更改飞书权限。

## 验收

商品咨询、付款核实、身份不匹配、开通失败、链接已发未授权、重复登记、到期漏处理、续购冲突、部分退款及跨商品越权都要走通。核对私有飞书资源和客户记录不出现在公开接口；用非站长账号验证复制/下载限制，且不把无法防止的截图说成已解决。
