# 03 · 公众号解锁与权限

> v2.0 · 待评审。推荐：少量指定文章需要解锁，其余正常阅读。

## 先区分三件事

“已经发布”决定文章是否对外存在；“已解锁”决定访客能否读正文；“站长登录”决定谁能编辑。这三件事互不替代。输入阅读验证码永远不能获得站长权限，填 API Key 也不会自动解锁文章。

| 内容 | 未解锁访客 | 已解锁访客 | 站长 |
|---|---|---|---|
| 已发布公开文章 | 全文 | 全文 | 阅读与管理 |
| 已发布解锁文章 | 标题、摘要、指定试读 | 授权范围内全文 | 阅读与管理 |
| 草稿、撤回版本、后台记录 | 不可读 | 不可读 | 后台可读 |

## 访客怎样解锁

1. 读到试读末尾，看到公众号名称、二维码、要回复的关键词，以及“已有验证码”输入框。
2. 手机用户可复制公众号名称与关键词、保存二维码；不用要求拿另一台手机扫码。
3. 在公众号获得码后回来输入。成功后留在原段落继续阅读；错误、过期或尝试太频繁分别说明原因。
4. 首版建议一次解锁一个明确标注的“阅读合集”，授权保留 7 天，本浏览器有效，不强制注册。清理浏览器或换设备需重新输入。具体期限是方案默认值，可调整。

首次配置由站长在后台建立合集、随机生成通用码，手动把码配置到公众号关键词回复。推荐每 30 天轮换一次，网站显示生效及失效时间。没有公众号时保持功能关闭，用模拟公众号流程完成开发验收；不声称已经接通公众号。

轮换流程：先生成待启用新码 → 修改公众号回复 → 网站启用新码；可给旧码最多 24 小时过渡期。普通换码不自动撤销已经发出的 7 天授权；“撤销全部授权”是另一个明确操作，确认后立即让旧授权失效。

## 两种方式的权衡

| 方案 | 好处 | 代价与限制 |
|---|---|---|
| 通用码，首版推荐 | 公众号关键词回复即可运营；没有注册步骤 | 会被转发，不能证明关注状态；站长需同步更新回复 |
| 一人一次码，后续可选 | 能限制重复兑换，可做更细的授权 | 需要核实公众号接口权限、接收消息和发码服务；仍不能绝对防止分享正文 |

“加密文章”在产品上建议称“解锁阅读”。我们实现访问控制，不承诺防截屏、防复制或绝对保密。需要严肃保密的材料不应发布到这个分发系统中。

## 为什么不照搬参考站的代码

JavaGuide 公开的 `GlobalUnlock.vue` 和 `UnlockContent.vue` 用前端可见高度与浏览器解锁状态控制阅读，配置中有解锁规则。这适合轻量阅读引导；我们还有 AI 和受限附件，需要服务器统一授权。只借鉴试读、关键词回复、解锁后继续阅读的流程，不复制它作为我们的权限底层。

来源：[GlobalUnlock.vue](https://github.com/Snailclimb/JavaGuide/blob/main/docs/.vuepress/components/unlock/GlobalUnlock.vue)、[UnlockContent.vue](https://github.com/Snailclimb/JavaGuide/blob/main/docs/.vuepress/components/unlock/UnlockContent.vue)，2026-09-20 读取公开源码，未尝试绕过网站限制。小林官网可确认公众号关键词领取资料，但本次没有证据确认其所有受限文章的后端实现，不能据此推断。[官网](https://xiaolincoding.com/)

## 服务器怎样守住边界

- 码只存服务端带秘密密钥的摘要，不放公开仓库、网页脚本或日志。使用足够长的随机码，并按浏览器会话及 IP 限速，不能只靠码难猜。
- 验证成功发出随机阅读会话，cookie 使用 HttpOnly、Secure、SameSite；数据库记录合集、到期时间、撤销版本。每次读全文都重新检查，不信任前端传来的 `unlocked=true`。
- 未解锁的 HTML、页面数据、预加载接口、搜索、RSS、站点地图及公开仓库均不含受限正文。受限请求使用私有、不缓存响应；不能让 CDN 把某人的全文给其他人。
- 默认 AI 不收受限正文。如果后续允许，必须在检索前、取段落时和生成前再次检查权限；旧聊天不能作为未经核实的受限知识继续送给模型。权限失效后拒绝新检索和续问，已发送的内容无法追回。
- 站长登录使用受控账号白名单；不能以“GitHub 登录成功”或 adu-works 仓库成员身份直接推导管理权限。管理员接口还检查会话和请求来源。

建议数据：`unlock_campaigns` 保存合集、码摘要与有效期；`reading_sessions` 保存随机会话摘要和授权。首版只支持一个默认合集，结构允许以后增设，但不提前做复杂会员等级。

接口：`POST /api/unlock` 接收码、目标合集，成功只设置安全 cookie；`GET /api/reading-access` 返回当前可读范围与到期时间。站长生成/启用码和撤销授权走独立管理接口，先展示影响再确认。错误输入返回 400，未登录 401，无阅读权限 403，限流 429；日志只记错误类型和请求 ID，不记码或会话原值。

## 怎样检查

未解锁、正确码、错码、过期、换码、撤销、换浏览器各测一次。更重要的是直接检查接口、页面源代码、搜索结果、受限图片和 AI 是否泄露正文；使用两个独立浏览器会话验证缓存隔离。不能只看输入框能否弹出“成功”。
