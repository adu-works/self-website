# 01 · 主站、文章与项目阅读

> v3.0 · 2026-09-20 个人出版与小店重设计，待评审。目标：外面好看，点进去也值得认真读。

## 访客看到什么

首页使用个人出版物的设计：姓名与定位、精选文章、最近文字、商品精选和作品入口。冷白底、深色文字与蓝色重点，留白和中文衬线标题形成节奏。主导航为首页、文字、作品、小店、关于；社媒在独立入口。首屏先回答“你是谁、值得读什么”，商品不抢走全部注意力。

文字覆盖技术与 AI、生活与认知、独立实践、商业与赚钱。作品页保留火星实验入口，但主站无需经过它。商品使用独立详情版式，明确目录、试读、价格、期限与人工交付；微信弹窗不自动弹出。

文章栏目有“全部 / 专题”、标题关键词搜索和少量标签。专题是一组有顺序的文章，比如示例专题“从零做一个网站”。每篇文章可属于一个主专题、有多个标签，避免一开始做复杂分类树。空列表显示写作中的提示，不用假文章凑数量。

| 页面 | 内容结构与视觉重点 |
|---|---|
| 文章 | 标题、摘要、更新日期 → 导语 → 分章正文 → 相关内容；宽屏右侧目录，手机可收起目录 |
| 项目 | 大幅项目视觉 → 要解决的问题 → 我的贡献 → 实现过程与证据 → 当前状态；不用文章模板硬套 |
| 专题 | 介绍、推荐起点、按顺序排列的文章；篇末有上一篇、下一篇 |
| 社媒 | 姓名与一句介绍、按平台列真实账号；未提供链接显示待补或隐藏，不跳平台首页冒充账号 |

正文支持图片及图注、代码复制、提示块、引文和对比表。控制行宽、留白和章节节奏；大图可展开，代码在自己的区域横向滚动，不撑坏手机页面。具体颜色和字体参考 v2.0.0 新原型；管理界面可简洁，但发布出来的文章不能只是编辑器的默认样式。

v2.2 商业流程：网站只呈现公开文章、商品介绍与获准试读，付费正文在飞书按账号阅读。购买咨询放在商品详情明确位置，由用户点击后打开微信弹窗，不在普通文章一进入就打断阅读。[商品与交付规则](03-access.md)。

## 页面如何往返

| 来路 | 返回到哪里 | 保留什么 |
|---|---|---|
| 首页打开项目 | 首页 | 滚动位置 |
| 列表打开文章 | 同一列表 | 搜索、标签、滚动位置 |
| Chat 点击引用 | 原来的对话 | 消息、输入草稿、对话滚动位置 |
| 文章中点击提问 | 指定文章范围的 Chat | 来源文章位置；切全站须明确提示 |
| 直接打开详情链接 | 对应文章或项目列表 | 不伪造“返回对话” |
| 关闭微信购买弹窗 | 原商品页 | 阅读位置 |

浏览器后退和前进遵守相同规则；“前往主站”“前往火星”是固定目的地。刷新后没有可靠来源时使用上表后备入口。内容不存在显示友好缺失页；已撤回内容不通过旧引用继续开放。

## 实现约定

正式路由建议 `/`、`/notes`、`/notes/[slug]`、`/series/[slug]`、`/projects`、`/projects/[slug]`、`/shop`、`/shop/[slug]`、`/about`、`/social`、`/chat`、`/explore`、`/admin`。当前原型仍用 hash 路由，不在本次文档整理中迁移。

文章每个章节有稳定 ID；改标题不随意改变 ID。AI 来源链接带文章、内容版本和段落标识。当前正文改变时提示“内容已有更新”，不把旧答案硬定位到不相关段落。首版不公开整套历史正文，避免撤回或权限变更后旧版泄露。旧 slug 保留跳转记录，避免普通改标题破坏外部链接。

全文、搜索结果、分享摘要都来自同一内容服务。首版使用中文关键词检索，标题和标签权重更高；受限内容只搜索公开摘要。检索不到结果时给清晰空状态，不用模型猜相关文章。

## 从参考站学什么

JavaGuide 的配置按文章路径或目录指定解锁范围；我们改成后台文章开关，避免每次修改配置文件。小林 coding 的公开仓库 README 按主题及学习顺序组织文章，适合借鉴为专题和上下篇。两者的内容组织值得学，但不照搬大型教程站导航，也不复制文章和图片。小林仓库未发现明确通用开源许可，公开可见不等于允许直接拿来使用。

来源（2026-09-20 核对）：[JavaGuide 解锁配置](https://github.com/Snailclimb/JavaGuide/blob/main/docs/.vuepress/features/unlock/config.ts)、[小林 coding 仓库](https://github.com/xiaolincoder/CS-Base)、[小林官网](https://xiaolincoding.com/)。本次核对公开页面与仓库，不声称已验证其私有后台。

### CS-Base 补充：落实到我们的页面

核对 main 分支完整目录后，仓库主要是 Markdown 文章、专题介绍及文字格式检查工作流，没有发现完整的网站应用或验证码后台源码。因此它主要用于参考内容结构，不作为可直接运行的 CMS 或权限系统。

- **专题先解释怎么读**：专题页增加简短的“适合谁、能学到什么、建议从哪篇开始”，参考其 `network/README.md`；允许直接搜索跳读，不强迫按顺序完成。
- **分清两种目录**：专题文章列表用于换文章，当前文章的章节目录用于定位段落。宽屏按需展开专题栏，手机用两个明确命名的抽屉，不挤成三列。
- **长文用图解帮助理解**：按问题分节，图紧跟相关解释，末尾可有小结；这是写作与排版建议，不要求每篇都套固定模板。内容仍由你提供或使用标注示例。
- **上下篇遵守实际可见顺序**：草稿和撤回文章不出现；需解锁文章显示已批准公开的标题与锁标记。没有下一篇就不显示假入口。

依据：[专题介绍原文](https://github.com/xiaolincoder/CS-Base/blob/main/network/README.md)、[图文文章样本](https://github.com/xiaolincoder/CS-Base/blob/main/network/1_base/tcp_ip_model.md)、[目录与源码](https://github.com/xiaolincoder/CS-Base)。以上是本项目的设计建议，未将参考仓库当作功能实现或用户批准。

## 怎样检查

逐一打开首页每种卡片，在手机与电脑检查长标题、长正文、大图和代码。检查同一详情从首页、列表和 Chat 三种来路的返回；直接分享链接仍可读。示例专题至少包含两篇文章以验证上下篇，空专题也有正确状态。

### TianPan.co 补充参考（2026-09-20）

核对首页、课程页、长文章、订阅介绍以及作者公开仓库。以下为设计建议，不代表已批准或已改原型：

- 首页突出一个清楚的个人方向，再用作品和文章支撑。我们主题可以广，但第一屏仍要有共同主线，不能只是栏目堆叠；具体定位由真实个人材料决定。
- 增加“从这里开始”的精选阅读路径，区别于按时间排列的最近文章。专题应解释读者能解决什么问题，再列阅读顺序。
- 免费文章可在相关位置连接一个匹配的商品及试读，不能每篇机械插入全部商品；没有相关商品就不显示。
- 篇末加入简短作者介绍、相关内容和关注入口，让搜索进入单篇的读者也能认识作者。关注内容更新与购买权益是不同动作，不混叫“订阅”。

参考站有 Free/Insider 课程标识、专题目录、RSS 和会员方案，但没有核验真实支付或后台权限。我们仍按逐商品微信人工成交设计，不因参考站存在会员套餐就切换为订阅制。

仓库结论：`puncsky/puncsky.github.com` 明确标为 deprecated，是旧站；`puncsky/system-design-and-architecture` 主要是内容、目录和构建文件，不是当前整站。作者架构文章提到 `packages/website` 与 `packages/chat-tianpan`，但此次未找到对应公开完整源码，不能当作可直接 fork 的模板或确认其当前技术栈。
