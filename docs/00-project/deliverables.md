# 开发所需交付物

> v0.1 · 2026-09-16。这是交付范围清单，不是提前编写的实现方案或工期承诺。

| 交付物 | 用途与完成标准 | 阶段 | 当前入口/状态 |
|---|---|---|---|
| PRD | 目标、受众、首版/后续、边界、验收条件 | G1 | [v1.0 待验收](../01-product/PRD-personal-site.md) |
| 功能与信息架构 | 页面、主路径、异常、权限、状态转换 | G1/G2 | [功能设计](../01-product/functional-design.md) |
| 内容与素材清单 | 谁提供什么、哪些可公开、缺什么 | G1 起 | [清单](../01-product/content-inventory.md) |
| 参考研究与设计提案 | 说明设计依据，选择体验方向 | G1/G2 | [现行完整方案](../02-prototype/experience-spec-v1.0.md)；历史参考研究保留 |
| 可点击原型 | 全部首版流程、手机与桌面、错误与空状态；模拟标记明确 | G2 | [v1.0 原型](../02-prototype/v1.0/README.md)，待验收 |
| 视觉与交互规范 | 字体、颜色、间距、组件、动效、响应式、减少动效 | G2 | [完整体验方案](../02-prototype/experience-spec-v1.0.md)已含规范 |
| 实现方案 | 技术取舍、模块、内容与数据模型、接口、模型/工具权限、索引更新、身份认证、成本限制 | G3 | 原型确认后写 |
| 开发规划 | 任务依赖、里程碑、每步可用成果、验证、估算依据与风险 | G3 | 原型确认后写；必须把两类 Agent 纳入首版完成线 |
| 测试与 AI 评估计划 | 功能、权限、回归、引用评估、失败恢复；关联需求编号 | G3 | PRD 已有验收提案，测试方案尚未制定 |
| 部署与维护说明 | 环境、配置、发布、备份、恢复、监控、费用与内容更新；不含凭据 | G3/G4 | 方案时设计、实现时记录实际操作 |
| 验收与发布记录 | 实测证据、缺陷、版本、用户批准的具体发布结果 | G4 | 不能用原型模拟提前填写通过 |
| SOP / 决策 / 学习日志 | 保存规则与真实经验，帮助用户独立修改 | 全程 | 持续维护，不另写一套冲突需求 |

现在需要补充的主要是功能状态、真实内容准备和验收可追踪性，已纳入本轮文档。API、数据库、部署说明在方案阶段集中写；没有需要就不单独增设重复文档。

## 目录维护规则

- README 负责导航，status 负责确认，PRD 负责范围，原型说明负责运行与评审。
- 历史稿留在明确的 history 或原历史位置并标注；不悄悄删除、覆盖成“从来如此”。
- 新原型使用新版本目录；不要继续把 v0.4 等覆盖进 v0.1。
- Sites 后续若采用，使用独立原型目录，避免在文档根目录初始化产品工程；正式源码结构由 G3 决定。
- 一次交付同步状态、交互约定与日志；没有批准证据不填写“已通过”。
