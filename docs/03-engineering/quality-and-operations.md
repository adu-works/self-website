# 验证、发布与维护方案

> v1.0 · G3 待评审。表内是验收要求，不是已通过的结果。

## 验收矩阵

| 需求 | 必测行为 | 验证方式 / 建议门槛 |
|---|---|---|
| R01–03 | 公开姓名、项目、文章、社媒；空数据不伪造 | schema fixtures + Playwright；七平台缺地址不可点击 |
| R02/R03/R12 | 当前案例/手记/信纸版式、长标题/代码/图片 | 390/768/1440px 视觉复核；键盘与 200% 缩放；无横向溢出 |
| R12 | 地形越坡、手握铲、负重放下、镜头不穿头 | 保留原型纯逻辑测试 + 实际帧观察，不以数学测试代替动作审美 |
| R12 | WebGL 失败、减少动效、弱网、跳过 | E2E 直接阅读始终可用；离场不继续渲染 |
| R04/05/13 | 三供应商真实请求/停止/失效/限流/跨范围 | provider contract tests + 小额度真实集成；mock 通过不等于供应商通过 |
| R04/05 | 引用落到依据、返回保留上下文 | 稳定块 ID、删除/改名/新版本/撤回回归 |
| R06 | 未授权不能生成管理提案或写入 | 匿名、普通登录、过期会话与越权 ID 的 API/RLS 测试 |
| R06 | 确认、取消、过期、冲突、重复、断网 | 并发 integration tests；同一确认只产生一次内容版本 |
| R06 | 索引失败、切换失败、缓存失败、恢复旧版 | 故障注入；旧版本可用，步骤状态不谎报 |
| 隐私 | Key 和正文不入日志/错误/存储 | canary 假 Key 测试，对抓取日志与前端存储扫描 |

开发遵循“纯逻辑先测试→最小实现→集成→人工视觉”。不为 CSS 文案写镜像测试；每个垂直任务必须可运行，提交中记录检查与限制。

## AI 评估集

先以本人批准的材料建立不少于 40 个问题：20 个有明确依据、8 个无资料、6 个跨范围、6 个注入/诱导越权。每条含 scope、允许的 evidence block IDs、必须拒答/澄清条件；训练提示与验收题分开。小语料时明确不能外推大规模召回质量。

建议发布门槛：有依据题检索 Recall@5 ≥ 90%；抽样事实陈述的引用支持率 ≥ 95%；不存在的 source ID、私有内容泄漏和管理写入越权均为 0；无资料题正确拒答 ≥ 95%。这些是目标，需用户评审，不是现有系统指标。不同供应商分别报告结果；任一供应商不达标则停用该适配并明确缺口，不能静默宣称首版完整。

对长答案由人工核对事实断言与出处，不仅检查“有引用”数量。每次内容分块、检索排序或系统提示变化重跑相关评估。注入文本作为引用材料出现也不得获得工具权力。

## 性能预算与可访问性

建议目标：公开阅读页移动端 p75 LCP ≤ 2.5 秒、CLS ≤ 0.1；Chat 首个响应延迟拆分本站检索/供应商时间，记录分位数但不承诺外部模型 SLA。场景资源独立加载，初始阅读不下载 3D 模型和大纹理。初始首屏 JS 预算 250KB gzip（不含探索模块），超预算需说明取舍。场景优先稳定 30fps，目标设备和网络在 M0 登记；不假定所有手机达到 60fps。

图像有 alt、按钮有语义与焦点、动画遵循 prefers-reduced-motion。视觉回归覆盖首屏、正文中段和底部，不能只截图首页。

## 环境与部署

开发/预览/生产使用不同数据库与 secrets；公开仓库只提交 `.env.example` 的变量名，不提交值。建议环境项：SITE_ORIGIN、数据库连接、Auth OAuth 参数、管理员 ID allowlist、站长模型密钥、provider endpoint allowlist、限流阈值。对外可公开的配置与服务端秘密分别命名和校验，服务密钥不能进入 NEXT_PUBLIC 命名空间。

CI：依赖锁定安装 → typecheck/lint → unit → integration（临时数据库 + migrations）→ build → E2E → 预览环境。供应商真实集成用受控测试 secrets 手动触发，不向外部 fork PR 暴露。依赖升级和数据库迁移分别可审查。

首版不自动生产发布：G3 通过→G4 实现→预览验收→用户确认具体版本/域名/受众→生产。GitHub 公开不自动使 Sites 或未来产品公开。当前 Sites 仅保留设计原型，本轮没有重新部署网站。

发布前备份数据库与素材清单，执行向后兼容 migration，再部署 app/worker，健康检查通过后启用内容流量。迁移采用 expand/contract；破坏性变更不和应用同一步上线。Node 自托管时需反向代理、流式不缓冲、超时与大小限制；托管平台也要核查 SSE 时限与任务 worker 支持。

## 恢复与日常操作

代码回滚：回到上一个已验证部署；内容回滚：新建恢复提案并显式确认；数据库灾难恢复：在隔离环境还原快照、核对 release/素材后再切换。三者不能相互替代。建议初始 RPO 24h、RTO 4h，实际服务能力与费用确认后锁定；上线前做一次真实恢复演练。

每天备份并每月抽查恢复；任务积压、发布失败、连续 5xx、限流激增和预算阈值告警。监控记录 requestId、provider、耗时、错误码、operationId 和步骤状态，不收集 Key、原始问题或完整提示词。指标保留期建议 30 天，站长操作记录建议 180 天，待评审。

运行手册必须能回答：站点不可用怎么回滚；问答失败如何区分厂商和本站；任务卡住如何核实再重试；索引过旧如何重建；泄漏凭据怎样撤销；从哪里恢复内容。上线证据落在 docs/04-delivery，不能预填“已通过”。
