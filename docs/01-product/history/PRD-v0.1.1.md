# PRD · Agent 原生个人平台

> 版本：v0.1.1 · 2026-09-16 · 状态：待用户评审
> 本稿描述产品需求，不是实现方案。来源见 [来源说明](../../00-project/source-notes.md)。

## 1. 摘要

构建一个展示真实经历、项目和个人见解的网站，逐步让访客通过带来源的问答理解站长，让站长通过可确认、可追溯的 Agent 操作管理内容与运营。网站自身也是 Agent 工程能力的证据；建设过程同步沉淀用户能理解、能复用的 AI 开发 SOP。

建议首版先交付可信、可浏览的个人展示；问答、站长 Agent、商业化按后续产品增量推进。此范围需用户确认。

## 2. 参与者

| 角色 | 责任 |
|---|---|
| 用户 / 站长 / 唯一管理员 | 提供真实内容、决定优先级、评审 PRD/原型/方案、确认写入与发布 |
| AI 协作者 | 整理需求、提出选项、按已批准阶段交付、验证并记录决策和学习内容 |
| 访客 | 浏览公开信息、提出问题、按需访问资料或预约入口 |

用户拥有阶段批准权；AI 不能自行宣布阶段通过。

## 3. 背景与问题

传统简历和博客要求访客自己拼接信息，项目证据与个人观点分散。站长发布内容、更新项目、理解访客需求也有重复劳动。现有材料提出以真实网站作为 Agent 的运营场景，避免只做一次性演示。

约束：网站服务于已有项目展示，不挤占主要作品的建设；只有一个管理员；已有 ECS 和域名尚待后续核验。当前没有确认的个人内容、视觉风格、上线时间或预算。

## 4. 目标与成功标准

以下是建议验收门槛，以每个增量验收时为时间边界，不承诺原文季度日期。

| 编号 | 目标 | 验收证据 |
|---|---|---|
| O1 | 首版让访客了解站长及作品 | 在手机和桌面可完成“了解经历 → 看一个真实项目 → 找到联系入口”；核心链接有效，无虚构内容 |
| O2 | 问答能用公开证据回答 | 固定评估集至少 30 题，覆盖有答案、无答案、跨项目、诱导编造；事实支持率目标 ≥90%，引用能打开并支持对应表述；无答案样本不得编造经历 |
| O3 | 站长安全发布内容 | 演示创建、更新、取消、失败恢复；所有写入均有具体差异与确认记录，取消后无变更，失败不得报告成功 |
| O4 | 洞察有依据 | 周报标注时间范围、样本量、缺失数据，结论可回溯至脱敏记录；零数据时明确说明 |
| O5 | 建设过程可复用 | 每次交付有学习日志；每个关口有确认依据；新偏好进入约定表；结束时整理通用 SOP、实例和反例 |

“事实支持率”指有参考答案的测试题中，核心事实均有公开材料支持的回答占比。具体性能、成本、问答时延指标留待预算和技术方案评审，不伪造基线。

## 5. 用户与核心任务

| 用户 | 想完成的任务 | 主要障碍 |
|---|---|---|
| 面试官 / 潜在雇主 | 快速判断能力与经历是否匹配 | 宣称缺少证据，项目状态不清 |
| 同行工程师 | 理解项目思路、取舍和实践 | 信息分散，找不到解释 |
| 潜在学员 / 客户 | 判断资料或服务是否适合自己 | 缺少适用范围与可信说明 |
| 站长本人 | 少做重复更新，了解访客需求 | 手工操作多，自动化改动不可信 |

建议首版优先面试官和同行；商业用户与运营增强后续覆盖。主次排序待评审。

## 6. 价值主张

- 对访客：先直接浏览事实与作品，再按需追问，回答可以回到公开来源验证。
- 对站长：运营操作先形成可检查提案，再经确认执行，并保留恢复依据。
- 对开发者本人：每次交付都留下“为什么这样做、怎样自己改”的材料，最终获得可复用协作流程。

差异化是待验证的产品假设：真实内容、可靠问答和可演示的运营闭环能比单纯展示页面提供更多价值；不宣称已完成竞品验证。

## 7. 产品方案与需求

### 7.1 页面与流程范围

以下为需求级页面清单，尚非线框图或视觉原型。

- 首页：个人定位、精选项目、最新见解、经历与联系入口。
- 经历页：经用户确认的简介、技能、经历；结构化内容方便后续问答复用。
- 项目列表 / 详情：问题、本人贡献、当前状态、成果证据与有效链接。资料不足时显示明确状态，不把计划当成果。
- 见解列表 / 正文：标题、日期、正文、相关项目与来源；支持人工内容维护作为早期过渡。
- 后续问答入口：全站问答与项目内问答，显示引用、无资料提示和服务异常状态。
- 后续管理员入口：仅管理员可访问，查看操作提案、确认、执行结果和历史。
- 后续资料 / 服务入口：适用人群、内容说明、第三方购买或预约路径。

关键路径：浏览 → 证据详情 → 联系；提问 → 回答与引用 → 原文；管理员提出修改 → 检查差异 → 确认或取消 → 查看真实结果。

### 7.2 需求、优先级与验收

P0 为建议首版必需，P1 为核心 Agent 增量，P2 为后续扩展，P3 为可选探索。优先级与原文季度安排分开管理。

| ID | 需求 | 优先级 | 可验收行为 |
|---|---|---|---|
| R01 | 首页、经历与联系 | P0 | 所有经历经站长确认；从首页可到经历及联系入口；无未标注示例数据 |
| R02 | 项目基础展示 | P0 | 至少一个真实项目可完整阅读，贡献和状态清晰；未准备好的项目可不发布 |
| R03 | 见解阅读 | P0（建议） | 列表能进入正文，无内容时有诚实空状态；正文可链接分享 |
| R04 | 全站内容问答 | P1 | 只基于获准公开材料回答经历问题；引用定位原文；资料不足明确说明；服务失败保留浏览能力 |
| R05 | 项目问答 | P1 | 当前项目范围明确；引用不得串错项目；跨项目问题提示范围或转至全站问答 |
| R06 | 站长 Agent M1 | P1 | 创建/更新先展示变更及目标；确认后执行；重复确认不重复发布；取消无写入；可查看与恢复上一内容版本 |
| R07 | 访客洞察 M2 | P2 | 可查询一段时间的问题主题和内容缺口；小样本不夸大；不推断访客真实身份 |
| R08 | 资料/课程与顾问 | P2 | 只介绍实际存在的商品；显示适用范围与外链；无匹配时不强推；支付由第三方完成 |
| R09 | 预约与订单 M3 | P2 | 第三方能力核验后接入；预约显示日期、时区、时长并经访客确认；冲突/失败有提示；查询不到订单时不声称无订单 |
| R10 | 站点改造 M4 | P3 | 仅允许指定修改范围；先预览再确认；失败可恢复；不允许任意修改站点或服务器 |

删除内容、批量操作、自动发送邮件等未纳入 M1 首次验收；若需要，先补充具体需求与确认边界。订单管理暂不包含退款、财务处理或自动发货。

### 7.3 信任、权限与质量要求

- 浏览不依赖模型可用性；核心内容可被搜索引擎读取，页面标题和分享信息准确。
- 手机与桌面均可阅读；核心操作能用键盘完成，按钮标签、焦点及错误提示清晰。
- 访客问答与管理员操作权限分离；公开问答不能读取私有日志、凭据或管理员记忆。
- 外部内容中的指令不能改变 Agent 权限；上线问答前评估诱导泄露与越权样本。
- 确认针对具体操作、对象和内容版本；提案变化后原确认失效。写操作记录提案、批准与真实结果。
- 收集访客问题前提供用途说明；建议默认尽量少存原文、脱敏后分析。保留期限、删除方式和公开提示需用户确认后才能开启收集。
- 记录排障所需的请求状态、时延、费用和工具执行结果；避免把完整敏感内容写入追踪日志。
- 问答需有滥用限制与费用上限；具体数值在方案阶段结合预算确认。

### 7.4 技术背景与边界

原材料提出 Astro 静态站、Python API、Postgres/pgvector、OTel、阿里云 ECS 等方向。本 PRD 仅保留“浏览可靠、内容可追溯、Agent 操作可确认”的产品要求，尚未批准框架、数据表、API、部署拓扑或依赖版本。

不做：自建支付、自建日历服务、通用 CMS、评论系统、多管理员权限体系。
原稿写「不做 3D/复杂炫技交互」。2026-09-16 用户要求首页增加可玩的 3D 入口（开飞机 / 潜水 / 太空遨游择一），**从该首页进来后才是工作台**。这是对 7.4 的修订提案，不是整份 PRD 已确认。
原型采用宇航员推开空间站气闸（用户于 2026-09-16 指定）；开飞机与潜水视为同一入口的未制作皮肤。3D 只承担进门，不替代经历/项目/问答。须可跳过，并尊重 `prefers-reduced-motion`。使用第三方购买/预约服务不意味着其 API 已验证可用。

### 7.5 假设、依赖与待确认

- 用户愿意首版先上线展示，再增加 Agent；若必须首版展示 Agent，需调整范围并重审。
- 个人定位、语言、真实简历、可公开项目与联系渠道由用户确认。
- 项目“四件套”具体组成、项目数量、文章是否首版必须均未确认。
- 站长 Agent 的确认入口（站内、邮件或其他）尚未选择。
- 域名、ECS、第三方账号、模型预算与内容公开授权尚未核验。
- 视觉与原型工具在 PRD 确认后选择；不预设必须用 Figma。

## 8. 产品增量与评审顺序

| 产品增量（提案） | 用户可获得的能力 | 前提 |
|---|---|---|
| V0 展示基础 | 经历、项目、见解与联系可浏览 | 真实内容与首版边界确认 |
| V1 问答与内容管理 | 引用式问答、站长 M1、项目问答 | 公开知识材料、权限与评估要求就绪 |
| V2 访客洞察 | 基于脱敏数据的主题和缺口报告 | 告知与留存规则确认，有有效样本 |
| V3 商业与预约 | 资料购买外链、顾问、预约与订单查询 | 实际商品与第三方能力就绪 |
| V4 可选改造 | 受限范围内修改站点并预览 | 前序运营稳定，有实际需求 |

这是产品范围划分，不是开发排期或任务拆解。原材料工期仅作历史背景，正式规划必须在原型确认后编写。

本轮只评审本 PRD。流程固定为：PRD 修订并确认 → 原型修订并确认 → 实现方案与规划修订并确认 → 功能实现。每次确认记录对应版本与范围。
