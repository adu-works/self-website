## 1. 产品目标

做一个有个人辨识度、能认真阅读作品、可以带来源对话的网站。站长通过 Agent 维护真实内容，所有写入先展示具体变更再确认；网站本身逐步成为可检查的工程作品。建设过程同步形成用户能够理解和独立修改的 AI 开发 SOP。

首版必须同时交付“展示 + 访客问答 + 站长内容管理”。允许内部按依赖逐步开发，但不能把只有静态展示的阶段成果称作首版完成。

## 2. 用户与任务

| 用户 | 主要任务 | 完成信号 |
|---|---|---|
| 访客（面试官、同行等，优先排序待确认） | 知道站长是谁、看真实作品、核对贡献、找到联系渠道 | 无需玩游戏或提问也能读完一个项目 |
| 对项目感兴趣的访客 | 就站长经历、文章、项目追问 | 回答附可打开的来源；材料不足时明确说明 |
| 站长（唯一管理员） | 创建文章、更新项目、检查并发布修改 | 能看清前后差异、取消、确认、检查结果和恢复旧版 |

## 4. 首版范围与验收

P0 表示建议的首版必要范围；“首版包含两类 Agent”已经确认，各子项与验收数值仍待评审。需求编号沿用旧稿，便于追踪。

| ID | 能力 | 范围 | 验收行为 |
|---|---|---|---|
| R01 | 首页、关于、联系 | P0 | 定位清楚；手机和桌面都能到达项目与联系；只有获准公开的真实经历；联系方式待提供 |
| R02 | 项目列表、详情 | P0 | 至少一个真实项目，分清问题、本人贡献、状态、证据；能直接分享详情；无项目时显示诚实空状态 |
| R03 | 文章列表、正文 | P0 提案 | 可阅读与分享；有日期及关联项目；无文章也有完整空状态；不编造文章库存 |
| R04 | 全站访客问答 | P0，已确认能力与自带 Key | 先完成访客模型配置； 只使用获准公开材料；回答带引用，打开能核对；资料不足、服务失败、限流均有独立状态；失败不影响普通浏览 |
| R05 | 项目内问答 | P0 提案 | 自动标明当前项目范围；跨项目问题经访客选择才切至全站；与全站问答共用信任约定 |
| R06 | 站长 Agent M1 | P0，已确认能力，操作边界待确认 | 仅管理员进入；从提供的材料生成文章或项目更新提案；展示差异和目标；确认、取消、失效、执行、失败与恢复均可检查 |
| R11 | 内容查找 | P0 提案 | 按标题或关键词查找公开项目与文章；无结果有明确提示；与 AI 问答分开标记 |
| R13 | 访客模型配置 | P0，已明确前置条件，具体策略待评审 | 厂商、Key、模型与必要接口信息；有效、无效、模型不可用、限流、取消和清除可区分；秘密不进入网址、船票、日志或分享；失败仍可阅读 |
| R12 | 视觉与基础体验 | P0 | 依据选定方向制作；有完整移动端和键盘路径；动效可减弱；场景不能挡住阅读；无强制声音 |

首版暂不纳入：R07 访客洞察、R08 商品/课程与产品顾问、R09 预约/订单、R10 Agent 改代码或样式。以上是后续候选；如用户需要其中任一首版能力，修改范围后再评审。首版公共导航不展示这些未实现能力，原型评审工具可单列历史演示。

## 5. 信息架构与核心流程

公共区域：首页 / 项目列表与详情 / 文章列表与正文 / 关于 / 联系 / 问答。内容查找是公共辅助功能。管理区域独立于访客导航，包含登录、站长对话、提案详情、执行记录与版本恢复。

普通浏览：首页 → 选择项目 → 阅读贡献与证据 → 联系。

访客问答：未配置时先配置模型并验证 → 选择范围 → 输入问题 → 等待 → 查看回答与来源 → 打开原文；失败可重试或继续浏览。项目问答沿用此流程，不把项目 A 的来源当成项目 B 的事实。

站长管理：登录 → 提供材料和目标 → Agent 生成提案 → 查看差异及预览 → 确认或取消 → 查看执行结果。内容保存成功、发布成功、问答索引更新成功分别显示，不用一个“成功”混淆结果。

具体页面行为与状态见 [功能设计](functional-design.md)。页面数量服从任务，不为了保留旧版 14 页而扩充首版。

## 6. 问答与写操作规则

### 访客问答

- 访客使用自己的模型配置与 API Key；访客凭据不得用于管理功能或其他人的请求。默认仅本次会话可用是提案，具体保存与请求通路在 G3 评审，不提前承诺不经服务器。
- 清楚展示请求目的地、发送内容与费用归属；验证由访客明确触发。配置失效可重配，保留输入与浏览入口，不要求重复游戏。原型仅模拟配置，禁止要求真实 Key。

- 仅使用公开授权材料。私有草稿、学习日志、管理记录、凭据默认不能进入问答范围；需公开时先经内容发布流程。
- 引用包含来源标题与可定位段落，引用目标应与回答一致；来源删除或变化时不得继续以旧回答作保证。
- 没有材料则明确说明，不推断未公开履历、指标或项目能力；不代站长承诺合作条件。
- 请求取消不再追加显示回答；失败保留当前输入；超过额度提示稍后再试并保留浏览入口。
- 首版不默认开启访客问题长期留存或洞察。模型供应商处理、必要运行日志、留存与删除规则在方案评审中写清，上线前落实。

### 站长 Agent M1（建议边界）

- 支持新建文章草稿、修改文章、修改项目描述；不自动删除内容、批量改动、发送邮件、改站点代码或购买服务。
- 提案必须含目标、操作、依据、修改前后内容、影响页面和内容版本。缺素材时提问，不补造事实。
- 预览与正式发布分开；确认绑定具体提案与版本。提案或目标内容变化后，旧确认失效。
- 重复点击不重复执行；取消不得写入；执行状态未知时先核对结果，不让站长盲目重发。
- 恢复旧版也展示差异、重新确认，并检查可能覆盖的新修改。记录真实执行结果与操作历史。
- 登录过期时阻止执行并保留待检查提案；重新登录不自动发布。访客无法通过输入指令获得管理权限。

## 7. 质量与验收提案

| 编号 | 检查 | 证据要求 |
|---|---|---|
| A01 | 从首页读项目并找到联系 | 桌面与手机各完整走通；内容真实性逐项核对 |
| A02 | AI 回答与引用 | 至少 30 题固定评估集，覆盖有答案、无答案、跨项目、服务失败、诱导编造与越权；有参考答案题事实支持率目标 ≥90%；无答案样本不得编造经历 |
| A03 | 访客权限 | 私有材料不可检索，访客请求无法调用管理写入；留下测试结果 |
| A04 | 管理闭环 | 新建、更新、取消、重复确认、版本冲突、登录过期、失败、结果未知、恢复均验证 |
| A05 | 阅读与无障碍 | 390px 手机及 1440px 桌面检查；200% 文本放大；键盘可操作、焦点可见、错误可读；关闭动效仍完成主路径 |
| A06 | 更新一致性 | 内容发布后详情页与问答来源更新；索引未更新时显示实际状态，不提前报告全部完成 |
| A08 | 自带 Key 闭环 | 配置成功/失败、取消、失效重配、清除与 Chat 返回主站；验证密钥不进入日志/URL/分享，访客间凭据隔离；原型只用假配置 |
| A07 | 可维护与教学 | 能按操作说明修改一个项目；每次交付有真实学习日志；发布有恢复步骤 |

以上尺寸、题数与门槛均为提案。性能、模型成本、并发限制和响应时限需结合预算在 G3 确定，本轮不虚构测量值。原型只演示状态，不能据此宣称 A02–A04 的后端验证已通过。
