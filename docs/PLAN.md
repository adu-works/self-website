## 每项功能的完成标准

状态顺序：未开始 → 实现中 → 待用户评审 →（需修改则返回实现中）→ 评审通过、教学待交付 → 闭环完成。

提交评审时登记：功能编号、实现提交、临时文档链接、真实测试结果与未完成事项。用户通过后再登记其明确原话、日期与批准范围；生成并检查正式教材，在同一提交中删除临时稿，补教材链接。教材没有交付不能勾选完成。会改变已批准行为的后续修改要重新评审受影响范围。

当前批准记录：**本轮没有任何 G4 功能批准或完成记录。** 注释和教学流程为用户本次明确指示；用户本轮原话：“哪种最优？TypeScript 全栈最优的话就使用TypeScript 全栈。”据此以当前项目维护成本为依据确定 TypeScript 全栈方向，范围仅为语言选择，不扩大为 G3 整体批准；起点提交为 `9509859`，本轮文档版本为 v3.4。
