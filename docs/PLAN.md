## 这轮改了什么

- 文章增加专题、连续阅读、Markdown 编辑与导入；文章与项目保留各自版式。
- 增加公众号解锁设计，把网页、搜索、附件、引用和 AI 的权限一起考虑。
- Agent 推荐复用 AI SDK；Codex 继续适合开发工作，不作为内容后台的运行时。
- 删去整站发布快照、独立发布 worker 等首版负担，改为单篇版本和事务。
- 合并旧 status、接口、质量、任务、交互及决策文件。重要取舍写在所属模块；历史从 Git 查，不再复制旧版本目录。

## 需要你决定的三件事

| 选择 | 我的建议 | 为什么需要你决定 |
|---|---|---|
| 1. 公众号解锁方式 | 少量精选文章需解锁，先用定期更换的通用码；无公众号时保持关闭 | 通用码会被转发；每人一次码需要公众号接口能力与额外开发 |
| 2. 解锁文章是否供 AI 问答 | 首版不供 AI，AI 只用公开内容 | 若开放，受限正文会发送给访客选择的第三方模型 |
| 3. 访客 Key 是否经本站转发 | 经过本站服务端，仅本次请求使用，不保存 | 这是真实的数据通路，必须在产品中向访客说明 |

技术库、表结构和任务顺序由方案承担，不再让你逐项选择。上面三项答复只确定受影响的设计；整份 v2.0 通过后，再记录明确的 G4 授权。个人资料、社媒、预算、域名和语言按你要求后补；预算和地区最迟在购买或部署验证前确定。

## 接下来按什么顺序做

以下均未开始。时间是单人持续投入的粗估，不是交付承诺；选择一次性发码会增加范围，完成第一步再重估。

| 阶段 | 可检查的成果 | 前置条件 | 估算 |
|---|---|---|---|
| M0 验证与补充评审 | 三厂商最小请求、部署可达性；文章编辑与解锁流程的小样 | v2.0 方案和开发范围明确批准；凭据安全配置 | 2–3 天 |
| M1 内容管理与阅读 | 示例文章从编辑、预览到发布；项目、专题、社媒及导航 | M0；不等待真实个人资料 | 5–7 天 |
| M2 阅读权限 | 试读、输码、授权到期、后台换码与撤回 | M1；公众号可用则联调，否则标注模拟渠道 | 3–4 天 |
| M3 访客 Chat | 多厂商配置、完整对话、来源定位、权限检查 | M1/M2；先把可读边界做对 | 4–6 天 |
| M4 站长 Agent | 读材料、给差异、确认存草稿、发布和恢复 | M1 内容服务；共用已有发布规则 | 4–6 天 |
| M5 火星与交付 | 迁移当前体验、手机检查、备份恢复、预览验收 | M1–M4；正式发布另确认具体结果 | 4–6 天 |

总计约 22–32 个工作日，实际受模型接入、场景迁移和反馈影响。内部每完成一个可用切片就给你检查，不必等整站结束；但两类 AI 都可用才算完整首版。

## 唯一任务清单

- [ ] M0：锁定依赖；验证部署区域、三厂商连接、流式取消及输入校验。
- [ ] M0：评审新增编辑、权限与解锁界面；既有火星与主站视觉基线保持。
- [ ] M1：接入站长认证并建立内容、版本、段落及素材结构，先测越权、版本冲突和发布事务。
- [ ] M1：完成文章编辑、导入、预览、发布、撤回与恢复；关闭 AI 仍能使用。
- [ ] M1：完成主站、详情、专题、搜索、社媒及全部返回关系。
- [ ] M2：完成阅读授权、码轮换、撤销与限流，检查附件和缓存。
- [ ] M3：完成厂商配置、会话、停止/重试、带来源回答，运行 30 题评估。
- [ ] M4：完成 Agent 只读工具、提案和确认执行，检查恶意材料与重复确认。

每项完成须有实际检查证据和对应学习日志。没有执行的测试不打勾；发现新问题只更新这里，不再生成第二份任务表。
