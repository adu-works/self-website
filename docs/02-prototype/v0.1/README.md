## 这是什么

一套可点击的静态原型，覆盖 PRD 7.1 的全部页面和 R01–R10 的关键状态。
没有后端、没有数据库、没有模型调用：所有"请求"都是页面内的定时器模拟，所有个人信息、项目、文章、数据都是**标注过的示例内容**。

形态是**空间站气闸 + 证据桌**：打开 `index.html` 先是宇航员走到气闸、把门推开，穿过后才落到深色桌面。桌上有问候、可点纸条、窗口、程序坞和 `⌘K`。
每个窗口装的就是下面表格里的页面，它们也都能单独打开（窗口标题栏右侧有“单独打开”）。

`prefers-reduced-motion`、WebGL 失败或点「跳过」，都会直接进桌面。

## 怎么打开

用本地静态服务器打开（窗口用 iframe 装载页面，`file://` 下部分浏览器会拦截）：

```bash
cd docs/02-prototype/v0.1
python3 -m http.server 4788
# 浏览器访问 http://localhost:4788/
```

端口用 4788，避开你本机 4173 上已有的服务。

## 设计方向

### 调研与两次转向

第一轮参照 rauno.me、paco.me（设计工程师的克制路线），做出来是一个排版干净的页面。用户看后指出方向不对，给了 11 个参照站。

旧 Agent 曾把这批站点归纳为“开场都是可玩场面”；此归纳已撤回。各站差异与本轮实际观察见上方设计提案。以下只保留当时的设计解释：

- `neilmin.com/zh`：深色、金光、第一人称「你好，我是…」
- `gkoberger.com`：桌上摊着能点的物件
- `alanagoyal.com/finder`、`sharyap.com`：桌面 / 窗口 / 自定义光标
- `merodev.net`、`wodniack.dev`、`animejs.com`：进入门槛与重编排动效
- `joshwcomeau.com`：颗粒、丘陵、气氛
- `bruno-simon.com`、`logartis.info`、`portfolio.ohevan.com`：场面感。用户随后要求 3D **只放在首页入口**，进来才是桌子；入口已定为宇航员推开空间站的门。

落到这个产品上的东西不是 Finder 克隆，而是**一张会跟着指针动的证据桌**。窗口系统用来并排打开项目与问答，纸条才是这个人的桌面。

### 为什么桌面隐喻适合这个产品

不是为了模仿而模仿——这个隐喻和产品内核是对上的：

- 项目和见解本来就是**文件**
- 站长 Agent 的「提案 → 差异 → 确认」本来就是**系统对话框**
- 全站问答本来就是**聚光灯搜索**
- 证据来源本来就该能**并排打开对照**

### 具体做法

- **签名交互**：正文主张后面挂等宽小编号（`H1`、`E1`、`A1`），指上去或键盘聚焦时，下方对应来源被**记号笔从左到右划过**标亮。首页标题本身就在演示这个动作——因为这就是这个站唯一的主张：说出口的事情要能被核对。
- **颜色**：近乎单色。墨黑 / 纸白（深色模式下反过来），只有一个暖琥珀作为记号色，外加三个语义色（已核实的绿、缺证据的琥珀、失败的砖红）各自只在状态处出现。
- **字体**：标题用 Newsreader + 宋体（拉丁与中文都是文献的字面），正文用系统无衬线，编号 / 时间戳 / 差异 / 状态用 JetBrains Mono。网络不可用时自动回退系统字体。
- **深浅双主题**：跟随系统，也可手动切换并记住选择。
- **动效清单**
  - 外壳：开机先出「你好。」（可跳过）；金光与纸条跟指针做低倍率视差；自定义环形光标（触控与窗口内退回系统光标）；程序坞靠近时放大；窗口从被点击的纸条/图标位置展开。
  - 页面内：问候字号错峰；滚动入场；主按钮轻微跟手；证据记号笔划过。
  - 全部只动 `transform` 和 `opacity`；`prefers-reduced-motion` 下开机与光标直接关掉。

### 评审标注开关

顶部那个「评审标注：开 / 关」按钮可以把需求编号、示例说明、状态切换器一起收起来，只留产品本身。
**看设计时请关掉它，评审流程时再打开。**

同时对照了 Apple 的界面与流体动效原则（按下即反馈、半透明层次、尺寸相关的字距行距、三种无障碍偏好）和 Web Interface Guidelines 的可访问性清单。
静态原型没有手势，所以弹簧与速度接力那部分没有硬套。

## 建议的评审路线（约 15 分钟）

0. **先看气闸**：打开 `index.html`，WASD 走向空间站的门，点门或按空格推开；或点「推开门」自动走过去。进来后才是桌子。再点纸条开窗口、试 `⌘K`。
1. **访客主路径**：在「首页」窗口里点"看项目证据" → 进项目详情 → 点"聊聊这个项目"。检查三步能否说明"这个人能做什么"。
2. **诚实状态**：`projects.html` 顶部切换"空状态"，看没有内容时页面说了什么；再看第三张"资料不足"的卡片。
3. **问答边界**：`ask.html` 依次选五种演示状态各问一次，重点看"无资料"和"越权请求"的措辞是否符合你的底线。
4. **写入确认**：`admin.html` 按页内提示做四件事——确认执行、重复确认、修改提案使确认失效、执行失败后恢复。这是 R06 的核心。
5. **状态索引**：`states.html` 对照表逐项检查是否有遗漏的异常场景。
6. **手机**：`mobile.html`，特别看管理端确认流程在手机上够不够用。

## 请你回答的问题

设计层面（先看这几个）：

0a. 宇航员推门这套入口是否就是你要的首页？要不要改成第一人称贴面罩，或干脆缩短成开门动画不能走？
0b. 开机序列留多久合适？现在 2.1 秒可跳过。面试官第二次来访要不要直接跳过？
0c. 桌面默认深色、有金光和纸条。浅色主题也在，开关在右上角。你更想让访客默认看到哪个？
0d. 标题里挂证据编号，是让人觉得严谨，还是觉得啰嗦？

原型层面：

1. 首页第一屏的信息顺序（定位 → 项目 → 见解 → 问答）对不对？有没有该前置的东西？
2. 项目的四段结构（问题 / 我的贡献 / 当前状态 / 证据）是否就是你要的"项目四件套"？字段名要不要改？
3. 问答的五种状态措辞能不能代表你？尤其"无资料"时是否愿意把访客推向联系页。
4. 管理端的确认粒度合不合适：一条提案一次确认，还是需要更细（例如逐字段确认）？
5. 洞察页默认"未开启收集"是否符合你的隐私偏好？
6. 后续能力（问答、管理端、洞察、商业化）在首版要不要在导航里出现"后续"标记，还是干脆不露出？

仍然卡在 PRD 的内容问题（这些不定，原型就只能一直是示例内容）：

7. 中文、英文还是双语？
8. 首版公开哪些项目和经历？简历是否公开下载？
9. 首版联系渠道用邮箱还是表单？

## 这个原型不代表什么

- 不代表视觉设计定稿：颜色、字体、间距是一个有明确理由的提案，欢迎推翻，但它不是“随便配的”。
- 不代表技术选型：静态 HTML 只是演示载体，框架、数据存储、部署方式要到第三阶段评审。
- 不代表能力已实现：带"后续"标记的页面全部是空壳演示。
- 不代表内容属实：所有个人信息都是占位，等你提供真实材料后替换。
