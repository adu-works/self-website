1. 问题

示例：访客想判断“这个人能不能做这件事”，但证据散落在简历、仓库和文章里，需要自己拼。说明问题时写清楚“对谁是问题、有多痛”，不要直接跳到方案。

2. 我的贡献

  • 示例贡献一：负责哪部分、做了什么决策。
  • 示例贡献二：遇到什么约束、怎么取舍。
  • 示例贡献三：明确写出不是我做的部分，边界清晰反而更可信。

3. 当前状态

示例：核心链路可用，评估集覆盖 30 题；尚未接入真实数据源。
状态描述要能被证据支持；说不清的部分写“未验证”。

4. 成果证据

  • A1示例：设计文档（原型中不可点）
  • A2示例：评估结果截图或表格
  • A3示例：可访问的线上页面
证据缺失时怎么写：“这项结果目前没有可公开材料”，而不是给一个打不开的链接或含糊的数字。PRD 要求核心链接有效、无虚构指标。
