# 设计提案 · 先选体验，再制作原型

> v0.3 · 2026-09-16 · 待用户选择；关联 PRD v0.3。依据 design-brief 技能组织。
> 用户本轮明确要求重新选方向，因此旧太空入口与桌面不作默认答案。

最新补充：用户提出[火星探索与 AI 船票](mars-journey.md)，对应 PRD v0.3 的访客自带 Key 要求。下方 A/B/C 保留为比较背景；火星是否成为选定主题仍待确认。

## 1. 要解决什么

做一个属于站长本人的网站，让人愿意探索，也能直接找到作品、读文章、向 AI 提问。站长管理端用于真实内容维护，视觉服务于检查和决策。

当前问题有直接证据：用户认为旧原型丑、很多决定未经确认；旧文档把多种参考站统称为“可玩场面”，随后把证据桌写成已选方向。此次先把事实观察、设计推论与待选方案分开。

受众暂以面试官、同行与愿意了解站长的人为设计假设；排序待确认。没有确认的品牌资产或真实个人内容，用明确标注的示例设计，不把参考网站作者的身份、照片或项目移植过来。

## 2. 参考站分析

2026-09-16 访问全部 11 个链接，第二轮进一步实际操作。详细的动作、结果和未走通部分见[深入交互记录](reference-interactions.md)。以下不是完整性能或移动端审计。

| 参考 | 实际体验重点 | 对本站的取舍建议 |
|---|---|---|
| [Neil](https://neilmin.com/zh/) | 搜索输入 RocksDB，打开匹配文章 | 明确身份、内容查找与正文路径 |
| [Gregory](https://gkoberger.com/) | 书本打开兴趣清单；Escape 返回；项目板打开作品面板 | 物件含义与内容一致，展开后聚焦阅读 |
| [Alana Finder](https://www.alanagoyal.com/finder) | 文件夹 → README → 独立阅读窗口；可拖动 | 桌面需要真实的层级与窗口秩序 |
| [Shar](https://www.sharyap.com/) | 拖动和滚动作品窗口，展开 FAQ | 借个人插画语言；专门检查窗口是否超出视口 |
| [Merodev](https://merodev.net/) | 立方体展开场景导航；进入作品列表并退出返回 | 场景可做导航，正文切为清晰平面布局 |
| [Bruno](https://bruno-simon.com/) | 已体验信息面板、地图与场景变化；未确认驾驶成功 | 世界体验包括控制说明与地图，不能只看开场 |
| [Logartis](https://logartis.info/) | 无声探索、滚动镜头、作品列表和详情、后退 | 氛围与直接导航共存，作品详情可有独立地址 |
| [Wodniack](https://wodniack.dev/) | WORK 导航后滚动到错落作品与巨幅文字 | 借比例与节奏；未确认作品外跳完整路径 |
| [Anime.js](https://animejs.com/) | 切换弹簧预设，查看曲线、示例和 CSS 输出 | 动效用可操作样例比较；不等于已选该库 |

| [Evan](https://portfolio.ohevan.com/) | 巨幅标题与摄影；BLOG 能进入独立博客，长页未走通 | 作品集与阅读布局可以不同；不据此宣称滚动质量 |

**结论（设计推论）**：这些参考至少覆盖内容阅读、桌面探索、场景体验、动效作品集四类。不能因为喜欢其中几个，就认定用户要全部效果拼在一起。

## 3. 三个可选方向

### A · 个人创作室（推荐提案）

**感觉**：进入一个有鲜明个人气质的创作空间，同时能直接阅读。用强版式、少量物件与一个有意义的动效建立记忆。

- 首屏：左侧大字号姓名与一句真实定位；右侧一个原创主视觉或精选项目实图；底部可直接看到精选作品入口；顶部保留项目、文章、关于、问答。
- 中段：一大一小的项目展示节奏；项目状态与本人贡献直接可读。文章回归平静的单栏，不重复首页表演。
- AI：明确“问问本站 AI”入口；桌面在阅读旁边打开问答面板，引用可定位当前内容；手机用整页问答并保留返回位置。
- 视觉提案：纸白 `#F5F5F2`、墨色 `#17191C`、钴蓝 `#3255E7`；中文用清晰黑体层级，少量衬线只用于短标题；不靠满屏卡片与徽章填充。
- 动效与物件：主视觉的动作对应内容含义；如采用物件，点击后打开相关内容面板，并可明确关闭返回。具体物件依据真实兴趣决定，不预设用户有某项爱好。阅读区域不跟着指针漂移。
- 手机：保留主视觉裁切与项目节奏，单栏自然滚动；不缩小一整张桌面。
- 参考组合：Wodniack/Evan 的版式力度 + Josh/Neil 的阅读组织 + Shar/Greg 的个人趣味。
- 代价：需要一个能代表你的视觉主题或真实项目截图；没有素材时先用清楚标注的设计占位，不虚构作品。

为什么推荐：两类 Agent 已在首版范围内。这个方向让公开内容与问答容易发现，也能在首页建立辨识度，不额外要求所有页面服从复杂窗口系统。

### B · 可探索的个人桌面

**感觉**：像打开一个人的电脑，项目、文章和兴趣是可打开的对象。

- 首屏：一份默认打开的简短欢迎页，周围是项目、笔记、问答三个主要对象；不先给一张空桌子让访客猜。
- 内容：项目与文章在阅读窗口打开，保留独立页面入口与链接分享；未实现的商品、日历和运营功能不出现。
- AI：问答窗口和证据窗口可以并排；站长管理独立入口，不把私人控制台混在游客桌面。
- 视觉提案：夜蓝 `#101B30`、浅灰白窗口 `#F8FAFD`、亮黄 `#F0CB55`；原创物件图标与统一窗口边框，不照搬 macOS 图标与壁纸。
- 动效：打开/关闭从对象位置过渡；少量拖拽用于探索，所有操作必须有点击或键盘替代。
- 手机：切为单面板与清晰返回导航，不保留重叠窗口。减少动效时直接切换面板。
- 参考：Alana Finder、Shar。与旧稿的差异在于默认内容、窗口秩序、原创资产和移动端信息组织，需要全套重做而不是换颜色。
- 代价：窗口焦点、尺寸、返回、分享与触控都需专项设计；正文空间较紧，原型验证工作更多。先验证“欢迎 → 文件夹 → 正文 → 返回”完整链，检查初次窗口是否全在视口内。

### C · 沉浸式个人展馆

**感觉**：进入一个有主题的小型场景，用一个独特动作认识站长，然后看作品。

- 首屏：一个原创场景与明确身份；“探索”和“直接看作品”同时可见；主题另选，不默认宇航员、潜水或驾驶。
- 内容：场景可以直接承担导航，点击物件进入对应项目；进入项目后保持清晰阅读，站内深链接不重新播放开场。无需强制“先看一段动画，再去普通首页”。
- AI：场景内的一个明确咨询入口，进入后是易读问答；不把 AI 变成需要寻找的隐藏彩蛋。
- 视觉提案：深炭色 `#15191D`、冷白 `#EDF3F6`、亮橙 `#FF743D`；空间光照与材质统一，页面只借用场景中的细节。
- 动效：一条主要镜头或探索路径；随时跳过、默认静音、加载失败切至普通内容；移动端以触控可用的简化场景呈现。
- 参考：Bruno、Logartis、Merodev；Anime.js 提供“聚焦一个主视觉”的动效启发。
- 代价：模型、材质、设备性能、加载与动作质量共同决定成败；应先评审一段关键体验，避免用基础几何体拼人物后称为精致。

| 维度 | A 创作室 | B 桌面 | C 展馆 |
|---|---|---|---|
| 第一眼重点 | 人与精选作品 | 个人物件与窗口 | 场景与探索 |
| 阅读/问答可发现性 | 强 | 依赖桌面组织 | 依赖直达入口 |
| 内容维护负担 | 相对低 | 中 | 高，额外维护场景资产 |
| 手机适配 | 自然单栏 | 必须专门设计面板模式 | 必须专门设计降级 |
| 下一份原型先验证 | 首页、项目详情、问答联动 | 欢迎页、窗口、手机切换 | 场景关键动作及跳过后页面 |

这是相对判断，不是工时承诺。三种方向都包含同一套首版功能，不用选择视觉方向来交换 Agent 能力。

## 4. 不随方向变化的体验约定（提案）

1. 访客在第一屏能知道是谁、能看什么、如何提问；无需掌握游戏控制或窗口手势。
2. 项目、正文、问答和管理端采用同一字体与色彩体系，但阅读区和管理区降低装饰密度。
3. 示例标签保持可见；评审编号可折叠，不能把“尚未接真实模型”一并隐藏。
4. 管理端有对话、提案与执行记录；提交前能检查完整差异，不能仅有漂亮的聊天气泡。
5. 关闭动效、加载失败、无内容、模型失败仍有可用路径。不能伪造证据完好或服务在线状态。

## 5. 新原型应交付什么

选定方向后，先做桌面首页、手机首页、项目详情与问答的代表性闭环供评审，再扩展全部首版页面和管理流程。原型清楚标注示例数据及模拟 AI；没有真实发布、发信、支付或管理员后端。

随原型补齐视觉规范（颜色、字体、间距、组件、动效与减少动效）、页面和状态映射、可操作的评审路线与已执行检查记录。用户评审决定审美是否通过，AI 检查只报告观察结果。

可用 Sites 提供独立原型预览，保留本地源文件。用户“可以借助 Sites”不等于批准正式站架构；此阶段不接真实业务写操作，也不发布用户未批准的真实个人内容。
